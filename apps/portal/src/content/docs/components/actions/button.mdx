The `Button` component triggers actions such as submitting, saving, deleting, opening a dialog, or starting and advancing a workflow. Use `Link` when the interaction navigates to a route, URL, file, or other destination. Ordinary navigation should not use Button, even when the control is visually prominent.

The label does not determine the semantic component. For example, use Button when “Get Started” begins or advances an onboarding flow in place. Use Link when “Get Started” navigates to an onboarding destination.

## Promise callback

When the `onClick` prop returns a promise, the button automatically shows a loading state until the promise resolves or rejects.

<DocsPage.ComponentExample
  client:only
  code={`<div className="flex flex-col items-start min-w-[600px] gap-cn-2xl">
<h4>Promise-based onClick Handlers</h4>

<div className="flex gap-cn-sm">
  <Button
    onClick={async () => {
      // Simulate API call
      await new Promise((resolve) => setTimeout(resolve, 2000));
      console.log("API call completed");
    }}
  >
    Save Data (2s)
  </Button>

<Button
  variant="secondary"
  onClick={() => {
    // Return a promise directly
    return fetch("/api/endpoint")
      .then((response) => response.json())
      .then((data) => console.log("Data:", data))
      .catch((error) => console.error("Error:", error));
  }}
>
  Fetch Data
</Button>

  <Button
    variant="outline"
    onClick={() => {
      // Promise that might reject
      return new Promise((resolve, reject) => {
        setTimeout(() => {
          Math.random() > 0.5 ? resolve("Success!") : reject("Failed!");
        }, 1500);
      });
    }}
  >
    Random Result (1.5s)
  </Button>
</div>

<hr />

<h4>Combined with Manual Loading State</h4>

<div className="flex gap-cn-sm">
  <Button 
    loading={true}
    onClick={async () => {
      await new Promise(resolve => setTimeout(resolve, 1000))
    }}
  >
    Always Loading
  </Button>
  
  <Button 
    iconOnly
    variant="ai"
    tooltipProps={{ content: "Ask AI" }}

    }}
  >
    <IconV2 name="ai-solid" skipSize />
  </Button>
</div>
</div>`}
/>

## Additional Features

When the `iconOnly` prop is used, you must also provide `tooltipProps` to display content in the tooltip.

Icon-only Buttons use the `default` theme. Do not apply `success` or `danger`; communicate semantic meaning through the accessible name, surrounding context, and feedback after activation.

If you need to skip showing the tooltip, you should set `ignoreIconOnlyTooltip`.

## Rounded icon-only Buttons

The `rounded` prop is supported for icon-only Buttons in `md`, `sm`, and `xs`. Use it with `iconOnly`, an accessible name, and the required tooltip or explicit tooltip override.

```tsx
<Button
  iconOnly
  rounded
  aria-label="Add node"
  tooltipProps={{ content: "Add node" }}
>
  <IconV2 name="plus" />
</Button>
```

### Deprecated: Rounded text Buttons

Rounded text Buttons are deprecated. Do not use them for new work.

For existing usage:

- Replace `<Button rounded>Label</Button>` with the equivalent standard text Button, such as `<Button>Label</Button>`.
- Preserve the Button's variant, theme, size, accessible name, and behavior while removing `rounded`.

The text combination remains available temporarily so teams can migrate existing usage. The `rounded` prop itself remains supported for icon-only Buttons.

## Keyboard focus

Button displays keyboard focus through the browser's `:focus-visible` state. This is an intentional code-only runtime state: Figma component sets should not add `focus` to their published state property or Code Connect mappings.

The code treatment uses:

- A 2px `focus` outline using `border.brand`.
- A 2px inset `gray.25` contrast ring.
- A -2px outline offset for every non-link variant; the link-style action keeps the browser's default outline offset.
- The Button's existing radius, content, variant, and theme.
- A raised stacking context so neighboring controls do not cover the indicator.

### Representative Figma focus specification

Create one detached reference example near the Button component documentation. This example communicates the runtime behavior for review and handoff; it is not a published Button variant.

| Attribute         | Specification                                                                |
| ----------------- | ---------------------------------------------------------------------------- |
| Label             | Focus specification                                                          |
| Base Button       | Enabled `md`, `primary`, default-theme text Button                           |
| Trigger           | Keyboard focus matching `:focus-visible`; do not show for pointer-only focus |
| Outer indicator   | 2px solid `border.brand` focus outline                                       |
| Inner contrast    | 2px inset `gray.25` ring                                                     |
| Offset            | -2px for the representative non-link Button                                  |
| Shape and content | Preserve the base Button radius, label, and layout                           |
| Publication       | Detached documentation example only; do not add a `focus` state variant      |

## Usage

```tsx
import { Button } from '@harnessio/ui/components'

// Default button
<Button>Default Button</Button>

// Primary button with themes
<Button variant="primary" theme="default">Primary Button</Button>
<Button variant="primary" theme="success">Success Button</Button>
<Button variant="primary" theme="danger">Danger Button</Button>

// Secondary button
<Button variant="secondary">Secondary Button</Button>

// Outline button with themes
<Button variant="outline">Outline Button</Button>
<Button variant="outline" theme="success">Success Outline</Button>
<Button variant="outline" theme="danger">Danger Outline</Button>

// Ghost button
<Button variant="ghost">Ghost Button</Button>

// AI button (a special variant for AI-related actions)
<Button variant="ai">AI Button</Button>

// Link-style action (still a Button; does not navigate)
<Button variant="link" onClick={showDetails}>Show details</Button>

// Transparent button (note: doesn't accept theme prop)
<Button variant="transparent">Transparent Button</Button>

// Button sizes
<Button>Medium Size Button (default)</Button>
<Button size="sm">Small Button</Button>
<Button size="xs">Extra Small Button</Button>

// Icon only button
<Button iconOnly tooltipProps={{ content: 'Add' }}>
  <IconV2 name="plus" />
</Button>

// Loading state
<Button loading>Loading Button</Button>

// Disabled state
<Button disabled>Disabled Button</Button>
```

## Supported combinations

- Primary, secondary, outline, and ghost text Buttons support default, success, and danger.
- AI and transparent text Buttons use the default theme only.
- Link-style Buttons use the default theme at md and sm only.
- All icon-only Buttons use the default theme only.
- Button sizes are md, sm, and xs.
- Rounded is supported for icon-only Buttons; rounded text Buttons are deprecated.

The Button contract and repository checks enforce these combinations for new source usage.
