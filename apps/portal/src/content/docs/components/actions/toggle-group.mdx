<TabItem label="Overview">

The `ToggleGroup` component groups a set of toggle buttons for switching between related states or options. It is composed of `ToggleGroup.Root` and `ToggleGroup.Item`, and supports single or multiple selection.

<DocsPage.ComponentExample
  client:only
  code={`
    <ToggleGroup.Root type="multiple" value={['2']}>
      <ToggleGroup.Item value="1" text="Option 1" />
      <ToggleGroup.Item value="2" text="Option 2" />
      <ToggleGroup.Item value="3" text="Option 3" />
    </ToggleGroup.Root>
  `}
/>

## Variations

### Types

The `type` prop defines the selection behavior: `single` (default) allows one active item, `multiple` allows several.

<DocsPage.ComponentExample
  client:only
  code={`

          <ToggleGroup.Item value="1" text="Option 1" />
          <ToggleGroup.Item value="2" text="Option 2" />
          <ToggleGroup.Item value="3" text="Option 3" />
        </ToggleGroup.Root>
      </Layout.Vertical>
      <Layout.Vertical gap="xs">
        <Text variant="heading-subsection">Multiple type</Text>
        <ToggleGroup.Root type="multiple" value={['2']}>
          <ToggleGroup.Item value="1" text="Option 1" />
          <ToggleGroup.Item value="2" text="Option 2" />
          <ToggleGroup.Item value="3" text="Option 3" />
        </ToggleGroup.Root>
      </Layout.Vertical>

`}
/>

### Controlled and uncontrolled

`ToggleGroup.Root` can be used as a controlled or uncontrolled component.

- **Controlled**: pass both `value` and the `onChange` handler to fully control the selection from outside.
- **Uncontrolled with default value**: pass `value` to set an initial selection; the component then manages its own state.
- **Fully uncontrolled**: omit `value` and the component manages its state entirely on its own.

<DocsPage.ComponentExample
  client:only
  code={`

      <Layout.Vertical gap="xs">
        <Text variant="heading-subsection">Controlled type</Text>
        <ToggleGroup.Root value="2" onChange={() => {}}>
          <ToggleGroup.Item value="1" text="Option 1" />
          <ToggleGroup.Item value="2" text="Option 2" />
          <ToggleGroup.Item value="3" text="Option 3" />
        </ToggleGroup.Root>
      </Layout.Vertical>
      <Layout.Vertical gap="xs">

### Variants

The `variant` prop controls the unselected appearance: `outline`, `ghost`, or `transparent`. The `selectedVariant` prop controls the style when an item is pressed, with options `primary` and `secondary`.

<Aside type="note">
  When `variant` is set to `transparent`, `selectedVariant` is ignored — the
  selected state also stays `transparent`, following the design specification.
</Aside>

### Unselectable

Pass `unselectable` to prevent users from deselecting the last remaining active item, keeping at least one option selected at all times.

<DocsPage.ComponentExample
  client:only
  code={`
    <ToggleGroup.Root type="multiple" value={['2']} unselectable>
      <ToggleGroup.Item value="1" text="Option 1" />
      <ToggleGroup.Item value="2" text="Option 2" />
      <ToggleGroup.Item value="3" text="Option 3" />
    </ToggleGroup.Root>
  `}
/>

### Icon only

Pass `iconOnly` on an item to size it to fit a single icon. When set, the `prefixIcon` is the only icon displayed and the `text` prop becomes the item's `aria-label`.

<DocsPage.ComponentExample
  client:only
  code={`
    <ToggleGroup.Root type="multiple" value={['2']}>
      <ToggleGroup.Item value="1" prefixIcon="plus" iconOnly text="Add" />
      <ToggleGroup.Item value="2" iconOnly prefixIcon="minus" text="Subtract" />
      <ToggleGroup.Item value="3" iconOnly prefixIcon="xmark" text="Clear" />
    </ToggleGroup.Root>
  `}
/>

### With tooltip

Pass `tooltipProps` on an item to wrap it in a `Tooltip`. It accepts the `title`, `content`, `side`, and `align` properties from `TooltipProps`.

<DocsPage.ComponentExample
  client:only

## Installation

```tsx
import { ToggleGroup } from "@harnessio/ui/components";

<ToggleGroup.Root
  type="multiple"
  value={["2"]}
  orientation="vertical"
  variant="outline"
  selectedVariant="secondary"
  onChange={() => {}}
>
  <ToggleGroup.Item
    value="1"
    text="Option 1"
    tooltipProps={{
      title: "Title",
      content: <p>This is a tooltip</p>,
    }}
  />
  <ToggleGroup.Item value="2" text="Option 2" />
  <ToggleGroup.Item value="3" text="Option 3" />
</ToggleGroup.Root>;
```

## Anatomy

All parts of `ToggleGroup` can be imported and composed as needed.

```tsx
<ToggleGroup.Root>
  <ToggleGroup.Item />
</ToggleGroup.Root>
```

- `ToggleGroup.Root` is the container. It sets the selection `type`, shared `variant` / `selectedVariant` / `size` / `orientation`, and owns the selected value(s).
- Each `ToggleGroup.Item` is a pressable button identified by a required `value`. It renders an optional `prefixIcon`, `text` label, and optional `suffixIcon`.
- Selection can be controlled (`value` + `onChange`), seeded (`value` only), or fully uncontrolled.

<Aside type="note">
  The change handler is `onChange` (not `onValueChange`). In `single` mode it
  fires with a `string`; in `multiple` mode it fires with a `string[]`.
</Aside>

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use a `ToggleGroup` when a small set of related options share one context (e.g. view or alignment switches).
- Match `type` to intent: `single` for mutually-exclusive choices, `multiple` when several can be active.
- Use `unselectable` when at least one option must always stay selected.

**Don't**

- Don't mix numeric and string item values — `value` is always a `string`; pass `['2']`, not `[2]`.
- Don't overload a group with many items — for long lists use a `Select` or menu instead.

## Accessibility

### Keyboard

- Focus moves between items with the arrow keys (roving tabindex), following the group's `orientation`. Items activate with <kbd>Space</kbd> or <kbd>Enter</kbd>.

### Labeling & semantics

- The group and its items expose their roles and pressed state through the underlying Radix Toggle Group primitive.
- In `iconOnly` mode the `text` prop becomes each item's `aria-label`; always provide it so icon-only items have accessible names.
