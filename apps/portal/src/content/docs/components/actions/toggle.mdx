The `Toggle` component is a button that switches between two states — selected and unselected. It supports variants, sizes, icons, and an optional tooltip, and can be used in controlled or uncontrolled mode.

<DocsPage.ComponentExample
  client:only
  code={`
    <Toggle text="Default"/>
  `}
/>

## Variations

### Controlled and uncontrolled

The `Toggle` component can be used in both controlled and uncontrolled modes. In controlled mode, the `selected` prop drives the toggle's state and `onChange` fires with the new boolean when the user activates it. In uncontrolled mode, `defaultValue` sets the initial state and the component manages its own state internally.

<DocsPage.ComponentExample
  client:only
  code={`() => {
    const [controlled, setControlled] = React.useState(false);
    const handleControlledChange = (selected: boolean) => {
      setControlled(selected);
    };

    return (
    <div className="space-y-cn-sm w-full">
      <div className="flex items-center gap-cn-md border-b border-cn-borders-3 pb-cn-sm">
        <span className="text-cn-size-2 text-cn-3 w-40 shrink-0 font-mono">controlled</span>
        <Toggle text="Controlled" selected={controlled} onChange={handleControlledChange} />
      </div>
      <div className="flex items-center gap-cn-md">
        <span className="text-cn-size-2 text-cn-3 w-40 shrink-0 font-mono">uncontrolled</span>
        <Toggle text="Uncontrolled" defaultValue={true} />
      </div>
    </div>

)}`}
/>

### Variants

The `variant` prop controls the unselected style: `outline`, `ghost`, or `transparent`. The `selectedVariant` prop controls the style when the toggle is selected, with options `primary` and `secondary`.

<Aside type="note">
  When `variant` is set to `transparent`, `selectedVariant` is ignored — the
  selected state also stays `transparent`, following the design specification.
</Aside>

### Sizes

The `size` prop controls the toggle's overall dimensions. Supported values are `md` (default), `sm`, and `xs`.

    <Toggle text="Toggle" prefixIcon="plus" suffixIcon="minus" />

### Rounded

Pass `rounded` to give the underlying button fully rounded corners.

<DocsPage.ComponentExample
  client:only
  code={`
    <Toggle text="Rounded" rounded />
`}
/>

### Icon only

Pass `iconOnly` to size the toggle to fit a single icon, suitable for icon-only buttons. When `iconOnly` is set, the `prefixIcon` is the only icon displayed and the `text` prop becomes the button's `aria-label`.

<DocsPage.ComponentExample
  client:only
  code={`
    <Toggle iconOnly prefixIcon="plus" text="Add" />
`}
/>

### With tooltip

Pass `tooltipProps` to wrap the toggle in a `Tooltip`. It accepts the `title`, `content`, `side`, and `align` properties from `TooltipProps`.

<DocsPage.ComponentExample
  client:only
  code={`
    <Toggle
      tooltipProps={{
        title: 'Title',
        content: <p>This is a tooltip</p>
      }}
      text="With tooltip"
    />
`}
/>

## Installation

```tsx
import { Toggle } from "@harnessio/ui/components";

<Toggle
  size="sm"
  variant="outline"
  selectedVariant="primary"
  rounded
  tooltipProps={{
    content: <p>This is a tooltip</p>,
  }}
  text="Toggle"
/>;
```

## Anatomy

`Toggle` renders a single pressable button that reflects a selected / unselected state.

- The button hosts an optional `prefixIcon`, the `text` label, and an optional `suffixIcon`. In `iconOnly` mode only the `prefixIcon` shows and `text` supplies the accessible label.
- The unselected appearance comes from `variant`; when selected, the button switches to `selectedVariant` (except for `transparent`, which stays transparent).
- Activating the toggle flips its state and fires `onChange` with the new boolean value. Provide `selected` to control the state yourself, or `defaultValue` to let the component manage it.

<Aside type="note">
  `onChange` receives the new selected state as a boolean (not a DOM event), so
  a handler reads the value directly: `onChange={(selected) => …}`.
</Aside>

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Give every toggle a `text` label; in `iconOnly` mode keep `text` set so the control still has an accessible name.
- Use a `Toggle` for a single on/off choice; reach for `ToggleGroup` when several related toggles form one set.
- Pair `selected` with `onChange` in controlled mode, or use `defaultValue` for uncontrolled — don't mix the two.

**Don't**

- Don't rely on colour alone (the `selectedVariant`) to signal state without a clear label or icon.
- Don't use a `Toggle` for actions that submit or navigate — use a `Button` instead.

## Accessibility

### Keyboard

- The toggle is a real `<button>`, so it is focusable and activates with <kbd>Space</kbd> or <kbd>Enter</kbd>.

### Labeling & semantics

- The pressed state is exposed to assistive tech (`aria-pressed` / `data-state`) by the underlying Radix Toggle primitive.
- In `iconOnly` mode the `text` prop becomes the button's `aria-label`; always provide it so the icon-only control has an accessible name.
