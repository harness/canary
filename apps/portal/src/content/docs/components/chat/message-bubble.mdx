The `MessageBubble` component displays conversational messages in AI and chat interfaces. It's a compound component — `MessageBubble.Root` sets the message role, `MessageBubble.Content` holds the body, `MessageBubble.Text` / `MessageBubble.Markdown` render the message, and `MessageBubble.Footer` carries actions like copy, edit, and timestamps. User and assistant messages get distinct styling and alignment.

## Anatomy

`MessageBubble` is a compound component. Compose the parts inside a `Root` that declares who the message is from.

```tsx
<MessageBubble.Root role="assistant">
  <MessageBubble.Content>
    <MessageBubble.Text>Here's the answer.</MessageBubble.Text>
  </MessageBubble.Content>
  <MessageBubble.Footer>{/* actions, timestamp */}</MessageBubble.Footer>
</MessageBubble.Root>
```

- **`MessageBubble.Root`** — the container. `role` (`user` / `assistant`) is a styling discriminator that drives the bubble's alignment and appearance; it's optional, and when omitted neither role style is applied. Extends `HTMLAttributes<HTMLDivElement>`.
- **`MessageBubble.Content`** — the body wrapper that carries the role-based content styling. Extends `HTMLAttributes<HTMLDivElement>`.
- **`MessageBubble.Text`** — renders the message as body text. Accepts the same props as `Text`, plus an optional `speed` for a typewriter reveal (character-by-character) when the child is a string.
- **`MessageBubble.Markdown`** — renders the message from a markdown string (its `children`) using `MarkdownViewer` at the small variant, for assistant replies that contain formatting or code.
- **`MessageBubble.Footer`** — a flexible row for actions (copy, edit), timestamps, or any custom content. Extends `HTMLAttributes<HTMLDivElement>`.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Set `role` on every `Root` so user and assistant messages align and read distinctly.
- Use `MessageBubble.Markdown` for assistant responses that include lists, code, or links; use `MessageBubble.Text` for plain conversational text.
- Keep `Footer` actions minimal and consistent (e.g. copy + edit + timestamp) so the pattern is predictable across the thread.

**Don't**

- Don't put primary content in the `Footer` — it's for secondary actions and metadata.
- Don't rely on the `role` styling alone to convey who is speaking in contexts where color/alignment isn't enough; include an author label or avatar nearby.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Keep timestamps in the `Footer` short and localized (e.g. "2:30 PM").
- For copy actions, pass the message's plain text to `CopyButton` so what's copied matches what's shown.

## Accessibility

### Labeling

- The component renders plain containers with no built-in author labeling. Convey who sent each message through visible cues — an author name, avatar, or the role styling — so the sender is clear without relying on color alone.

### Known limitations

- **No live-region announcements.** `MessageBubble` adds no `aria-live`, so newly arriving messages aren't automatically announced by screen readers. If you're streaming assistant replies, manage an appropriate live region at the conversation level.
- **`role` is styling only.** The `role` prop is a visual discriminator (`user` / `assistant`), not an ARIA role — it doesn't change the element's accessibility semantics.
