The `PromptInput` component is a compound component for AI chat interfaces. It includes a textarea with auto-resize, keyboard shortcuts, and an optional toolbar for actions.

## Variations

### With toolbar and button

Put tool buttons inside `PromptInput.Tools`. Each `PromptInput.Button` is an icon-only toggle for a toolbar action (attach, mention, and so on).

### Streaming state

Pass `status="streaming"` to `PromptInput.Submit` while a response is generating. The submit icon becomes a stop icon so the same control cancels the stream.

## Anatomy

`PromptInput` is a compound component. `PromptInput.Root` is a real `<form>`; the textarea and toolbar are composed inside it.

```tsx
<PromptInput.Root onSubmit={handleSubmit}>
  <PromptInput.Textarea placeholder="What would you like to know?" />
  <PromptInput.Toolbar>
    <PromptInput.Tools>
      <PromptInput.Button prefixIcon="plus" tooltipProps={{ title: "Add" }} />
    </PromptInput.Tools>
    <PromptInput.Submit />
  </PromptInput.Toolbar>
</PromptInput.Root>
```

- **`PromptInput.Root`** — the form wrapper. It renders a native `<form>` and forwards standard form attributes, including `onSubmit`. It holds no value state of its own.
- **`PromptInput.Textarea`** — an auto-resizing textarea. It grows with its content, submits the form on `Enter`, and inserts a newline on `Shift + Enter`. Its field name is `message`.
- **`PromptInput.Toolbar`** — a container that lays out the tools on the left and the submit button on the right.
- **`PromptInput.Tools`** — a container for toolbar buttons.
- **`PromptInput.Button`** — an icon-only toggle for a toolbar action.
- **`PromptInput.Submit`** — the submit button. It shows a send icon by default and a stop icon while `status="streaming"`.
- **`PromptInput.Tags`** — an optional row of removable tags (for example, attached context), rendered when you pass a non-empty `tags` array.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Keep the placeholder short and action-oriented ("Ask me anything…").
- Switch `PromptInput.Submit` to `status="streaming"` while a response generates, so the control doubles as a stop button.
- Group related toolbar actions inside `PromptInput.Tools`, and give each `PromptInput.Button` a tooltip so its icon reads clearly.

**Don't**

- Don't add a separate submit `<button>` — `PromptInput.Submit` already submits the form, and the textarea submits on `Enter`.
- Don't rely on the toolbar for critical actions on very narrow layouts where the buttons may crowd the submit control.

## Content

{/* TODO: editorial — please review against product guidance. */}

- The textarea placeholder should describe what the person can ask, not label the field ("Ask me anything…", not "Prompt").
- Give each toolbar button a concise tooltip title that names the action ("Add", "Attach", "Mention").

## Accessibility

### Keyboard

- **`Enter`** submits the form; **`Shift + Enter`** inserts a new line.
- The toolbar buttons and submit control are standard buttons, reachable and activatable with the keyboard in the usual way.

### Labeling

- `PromptInput.Textarea` is not labeled on its own — the placeholder is not a substitute for an accessible name. Pass a `label` (or `aria-label`) so the field is announced.
- `PromptInput.Submit` and `PromptInput.Button` are icon-only. Give the submit control an `aria-label` (for example, "Send" / "Stop"), and give each toolbar button a `tooltipProps.title` (which names the toggle).

### Known limitations

- The component does not set an accessible name on the textarea or the submit button for you. Provide those in the surrounding markup.
