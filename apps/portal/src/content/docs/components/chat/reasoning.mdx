The `Reasoning` component displays AI reasoning or thinking content in a collapsible format. It automatically tracks streaming duration and can auto-collapse when streaming completes. It's a compound component with `Reasoning.Root`, `Reasoning.Trigger`, and `Reasoning.Content`.

<DocsPage.ComponentExample
  client:only
  code={`<Reasoning.Root defaultOpen={true}>
  <Reasoning.Trigger />
  <Reasoning.Content>
    Let me think about this step by step...

    1. First, I need to understand the problem
    2. Then, I'll analyze the options
    3. Finally, I'll provide a solution

  </Reasoning.Content>
</Reasoning.Root>`}
/>

## Variations

### Streaming state

When `isStreaming` is true, the trigger displays an animated shimmer effect. The component tracks the duration automatically.

<DocsPage.ComponentExample
  client:only
  code={`<Reasoning.Root isStreaming={true} defaultOpen={true}>
  <Reasoning.Trigger />
  <Reasoning.Content>
    Processing your request and analyzing the data...
  </Reasoning.Content>
</Reasoning.Root>`}
/>

### With duration

After streaming completes, the component displays how long the thinking took.

<DocsPage.ComponentExample
  client:only
  code={`<Reasoning.Root duration={5} defaultOpen={false}>
  <Reasoning.Trigger />
  <Reasoning.Content>
    After careful analysis, here's my reasoning:

    - The input appears to be valid
    - Processing was successful
    - Results are ready

  </Reasoning.Content>
</Reasoning.Root>`}
/>

### Custom thinking message

Customize the thinking message using the `getThinkingMessage` prop on the trigger.

<DocsPage.ComponentExample
  client:only
  code={`<Reasoning.Root isStreaming={false} duration={3} defaultOpen={false}>
  <Reasoning.Trigger
    getThinkingMessage={(isStreaming, duration) => {
      if (isStreaming) return <Shimmer duration={1}>Processing...</Shimmer>;
      return <span>Analyzed for {duration}s</span>;
    }}
  />
  <Reasoning.Content>
    Custom reasoning content here.
  </Reasoning.Content>
</Reasoning.Root>`}
/>

## Installation

```typescript jsx
import { Reasoning } from '@harnessio/ui/components'

// Basic usage
<Reasoning.Root>
  <Reasoning.Trigger />
  <Reasoning.Content>
    Your reasoning content here...
  </Reasoning.Content>
</Reasoning.Root>

// With streaming state
const [isStreaming, setIsStreaming] = useState(true)

<Reasoning.Root isStreaming={isStreaming}>
  <Reasoning.Trigger />
  <Reasoning.Content>
    {streamingContent}
  </Reasoning.Content>
</Reasoning.Root>

// Controlled open state
const [open, setOpen] = useState(false)

<Reasoning.Root open={open} onOpenChange={setOpen}>
  <Reasoning.Trigger />
  <Reasoning.Content>
    Controlled content visibility
  </Reasoning.Content>
</Reasoning.Root>
```

## Anatomy

`Reasoning` is a compound component built on Radix UI's collapsible. `Reasoning.Root` manages the streaming and open state; the trigger shows the thinking header, and the content holds the reasoning body.

```tsx
<Reasoning.Root isStreaming={isStreaming}>
  <Reasoning.Trigger />
  <Reasoning.Content>{reasoningText}</Reasoning.Content>
</Reasoning.Root>
```

- **`Reasoning.Root`** — the container that manages state and provides context. Set `isStreaming` while the model is thinking; the component tracks duration and can auto-collapse once it finishes. Open state is uncontrolled (`defaultOpen`, default `true`) or controlled (`open` + `onOpenChange`).
- **`Reasoning.Trigger`** — the clickable header. By default it renders a chevron followed by a thinking message; while streaming, that message is a shimmer. Use `getThinkingMessage` to customize it, or pass `children` to replace it entirely.
- **`Reasoning.Content`** — the collapsible body. It renders its children as-is inside a scrollable region and auto-scrolls to the bottom while streaming.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Keep `isStreaming` in sync with the model's state so duration tracking and auto-collapse work as intended.
- Let the reasoning collapse after it completes — it's supporting detail, not the primary answer.
- Use `getThinkingMessage` when you want a domain-specific label ("Reviewing your code…") instead of the generic "Thinking…".

**Don't**

- Don't put the final answer inside `Reasoning.Content`; reserve it for the intermediate thinking.
- Don't rely on Markdown formatting in the content — it renders as plain content, not parsed Markdown.

## Content

{/* TODO: editorial — please review against product guidance. */}

- `Reasoning.Content` renders whatever node you pass without Markdown parsing. If you need formatted output, render your own formatted nodes (for example, a Markdown viewer) inside it.
- Keep the trigger message short and in the present or past tense that matches the state ("Thinking…" while streaming, "Thought for 5 seconds" after).

## Accessibility

### Keyboard

- The trigger is a real `<button>` (via Radix collapsible): it's focusable and toggles the content with `Enter` / `Space`.

### Labeling

- Radix wires the trigger's `aria-expanded` and `aria-controls` to the content region, so the expanded/collapsed state is announced.

### Behavior

1. **Auto-duration tracking**: when `isStreaming` transitions from `true` to `false`, the component calculates and displays the elapsed time (unless you pass an explicit `duration`).
2. **Auto-collapse**: the component collapses on each transition from streaming to complete, so a finished reasoning block folds itself away.
3. **Shimmer animation**: the default trigger message shows a shimmer while streaming to indicate ongoing activity.

### useReasoning

Access the reasoning context from within child components. Throws if used outside a `Reasoning.Root`.

```typescript jsx
import { useReasoning } from '@harnessio/ui/components'

const CustomComponent = () => {
  const { isStreaming, isOpen, duration } = useReasoning()

  return <div>Streaming: {isStreaming ? 'Yes' : 'No'}</div>
}
```

Returns `{ isStreaming: boolean; isOpen: boolean; duration: number | undefined }`.
