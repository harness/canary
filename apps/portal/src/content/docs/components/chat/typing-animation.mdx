The `TypingAnimation` component reveals text one character at a time, simulating real-time text generation. It's commonly used for AI assistant responses and chat interfaces. Since it extends the `Text` component, it accepts all of Text's styling props.

<DocsPage.ComponentExample
  client:only
  code={`<TypingAnimation text="Hello! How can I help you today?" />`}
/>

## Variations

### Custom speed

Control the typing speed with `typingSpeed` (milliseconds per character).

<DocsPage.ComponentExample
  client:only
  code={`<div className="flex flex-col gap-cn-md">
  <TypingAnimation text="Fast typing (25ms)" typingSpeed={25} />
  <TypingAnimation text="Default typing (50ms)" typingSpeed={50} />
  <TypingAnimation text="Slow typing (100ms)" typingSpeed={100} />
</div>`}
/>

### With delay

Add a delay before the animation starts with `delay` (milliseconds).

<DocsPage.ComponentExample

## Installation

```tsx
import { TypingAnimation } from "@harnessio/ui/components";

// Basic usage
<TypingAnimation text="Hello, world!" />

// With custom speed and delay
<TypingAnimation text="Welcome to the chat!" typingSpeed={30} delay={500} />

// With a completion callback
<TypingAnimation
  text="Processing complete."
  onComplete={() => console.log("Typing finished!")}
/>

// With Text styling
<TypingAnimation text="Important message" variant="heading-small" color="foreground-1" />;
```

## Behavior

- **Plays once.** The typing effect runs a single time. After it completes, later re-renders of the same instance show the full text immediately.
- **Changing `text`.** If `text` changes _before_ the first animation finishes, it resets and replays with the new value. Once the animation has completed, a new `text` value is shown immediately without replaying.
- **Line clamping.** The component applies `lineClamp={1}` by default to reduce layout shift as characters are revealed. You can override it by passing your own `lineClamp`.

<Aside type="note">
  `onComplete` fires when the last character has been revealed. It does not fire
  when text is shown immediately (for example, on a re-render after the
  animation has already completed).
</Aside>

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use it for streamed or assistant-style responses where the reveal reinforces that content is being generated.
- Keep `typingSpeed` fast enough that readers aren't waiting on the effect — the default of 50ms works for short messages.
- Override `lineClamp` when the message is expected to wrap across multiple lines.

**Don't**

- Don't animate long-form or critical content a user needs to read immediately — the reveal delays comprehension.
- Don't rely on the animation replaying when `text` changes after it has finished; it won't.

## Accessibility

### Labeling & semantics

- The text is revealed character by character in the DOM and is **not** wrapped in an `aria-live` region, so assistive tech is not notified as it types, and there is no `prefers-reduced-motion` handling. Treat the animation as decorative.
- When the message content matters for assistive tech, expose the full `text` through a live region or a visually-hidden node you control, rather than depending on this component to announce it.
