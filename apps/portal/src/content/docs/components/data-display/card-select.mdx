The `CardSelect` component provides an accessible, customizable card-based selection interface. It supports both single and multiple selection modes with flexible layouts (horizontal, vertical, or grid), making it suitable for forms, settings, and decision workflows.

## Anatomy

`CardSelect` is a compound component. A `CardSelect.Root` holds the selection state and lays out any number of `CardSelect.Item` cards; each card holds a `CardSelect.Title` and, optionally, a `CardSelect.Description`.

```typescript jsx
<CardSelect.Root type="single">
  <CardSelect.Item value="a" icon="git-branch">
    <CardSelect.Title>Option A</CardSelect.Title>
    <CardSelect.Description>Supporting detail</CardSelect.Description>
  </CardSelect.Item>
  <CardSelect.Item value="b" logo="gitlab">
    <CardSelect.Title>Option B</CardSelect.Title>
  </CardSelect.Item>
</CardSelect.Root>
```

- **Root** — a `<div>` that owns the selection value and shares it with the items via context. It sets the group role (`radiogroup` for `type="single"`, `group` for `type="multiple"`), and applies the `layout` and `gap` variants. For `layout="grid"`, `cols`/`rows` are passed through as CSS custom properties. Root works controlled (`value` + `onValueChange`) or uncontrolled (`defaultValue`).
- **Item** — the selectable card. It renders as a `<label>` acting as the control itself: `role="radio"` or `role="checkbox"` depending on the group `type`, with `aria-checked`/`aria-disabled` and its own keyboard handling. It contains an optional `icon` **or** `logo` (icon wins if both are given), the title/description, a "Coming Soon" badge when `comingSoon` is set, and a check mark when selected. A visually hidden native `<input>` inside the label carries the `name`/`value`/`checked` so the selection participates in form submission.
- **Title** — a `<div>` for the card's heading.
- **Description** — a `<div>` for supporting text beneath the title.

A few behaviors worth knowing:

- Selecting works like the native analog: `single` keeps exactly one item checked; `multiple` toggles items in and out of an array.
- By default `single` is "sticky" — re-clicking the checked item keeps it selected. Set `deselectable` on Root to let a second click clear the selection (it fires `onValueChange(null)`).
- `comingSoon` overrides `disabled`: the item is always non-selectable and shows the badge.
- `glow` only renders its ring while the item is checked.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use `type="single"` when exactly one choice is required, and `type="multiple"` when several can be picked at once.
- Keep each card's title to a short, scannable label and use the description for one line of supporting detail.
- Give the group a visible heading or label nearby so people know what they're choosing (see the accessibility note — the group has no built-in label).
- Use `comingSoon` to preview options that aren't available yet, rather than hiding them, so users know they're on the roadmap.

**Don't**

- Don't mix icons and logos arbitrarily across cards in the same group — keep the visual treatment consistent.
- Don't use Card Select for long lists of options; a [Select](/components/form/select/) or [Multi Select](/components/form/multi-select/) scales better past a handful of choices.
- Don't rely on the glow or check mark alone to convey selection — keep the labels and states clear for everyone.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Write titles as concise option names, not sentences ("Kubernetes", "Amazon ECS").
- Use the description for a single clarifying line; move longer explanations elsewhere.
- Use sentence case for descriptions, and keep parallel structure across cards in a group.

## Accessibility

`CardSelect` ships selection semantics out of the box: the group carries a `radiogroup`/`group` role and each card exposes a `radio`/`checkbox` role with its checked and disabled state.

### Keyboard

- Each enabled item is in the tab order (`tabindex="0"`); disabled items are removed from it (`tabindex="-1"`).
- **Space** or **Enter** on a focused item selects it (or toggles it, in `multiple` mode).

### Labeling

- Each item's accessible name comes from the text inside it — the `Title` and `Description` render within the `<label>`, so screen readers announce them as the option's name.
- The check mark, glow ring, and "Coming Soon" badge are visual affordances; state is also conveyed through `aria-checked`, `aria-disabled`, and the badge text.
- Icons and logos are decorative next to the text label.

### Focus & states

- Items show the standard keyboard focus ring, and selected/disabled/coming-soon states each have distinct styling in addition to their ARIA attributes.
- The group tracks a single roving selection for `single` and an array for `multiple`; the underlying hidden inputs share a common `name` so the choice submits with a form.

### Known limitations

- **The group has no built-in accessible name.** `CardSelect.Root` renders the `radiogroup`/`group` element but doesn't accept or forward `aria-label`/`aria-labelledby`, so the group itself is unlabeled. Provide a visible heading and associate it yourself (e.g. wrap the group in a labelled `fieldset`/`legend`) so assistive tech announces what the choice is for.
- **No arrow-key navigation between options.** Unlike a native radio group, every enabled card is a tab stop and there's no arrow-key roving — you move between options with **Tab**, not the arrow keys. This departs from the usual radio-group interaction pattern.
- **Extra props land on the hidden input, not the card.** `CardSelect.Item` spreads any extra HTML attributes onto the visually hidden, `aria-hidden` `<input>` rather than the visible `<label>`, so `aria-*` or `id` passed to `Item` won't reach the element assistive tech actually reads. Put descriptive text in the `Title`/`Description` instead.
