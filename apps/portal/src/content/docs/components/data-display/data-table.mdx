The `DataTable` component provides a data-driven way to display and interact with tabular data, featuring row selection, expansion, sorting, and custom cell rendering. Built on [TanStack Table](https://tanstack.com/table/latest), you describe your `columns` and hand it your `data` — it builds the underlying [Table](/components/data-display/table-v2/) for you. Reach for the composable [Table](/components/data-display/table-v2/) instead when you want to lay out rows and cells by hand.

## Variations

### Column visibility

### Grouped headers

Build multi-row column headers with TanStack Table's nested `columns` API — a parent column with a `columns` array becomes a header group. Give every parent and child an explicit `id`, set `enableSorting: false` on parent columns, and keep sorting state keyed by leaf column `id`s. Ungrouped top-level columns (and injected select/expander columns) span both header rows automatically.

Return a URL from `getRowLink` to make rows navigable — rows then render as links. Rows disabled via `getIsRowDisabled` are excluded from link rendering. `getRowLink` and `onRowClick` can coexist; the link takes precedence for navigation.

Pass a `columnPinning` state (`{ left, right }`) to pin columns to either side so they stay visible during horizontal scrolling. Pinned columns get a subtle shadow. Set explicit column `size` values for the best control, and avoid pinning so many columns that the scrollable area shrinks too far.

### Row pinning

Opt in to **bottom** row pinning via TanStack's `rowPinning` state — designed for a grand-total row that stays visible at the bottom. Append the total row to `data` and list its `getRowId` id in `rowPinning.bottom`; pair with `stickyHeader` so the header and total frame the scrolling body. Bottom pinning supports a single row — if multiple ids are listed, only the last one renders.

## Anatomy

`DataTable` is a single, data-driven component — you don't compose parts. You describe the shape of each column with a TanStack `ColumnDef` array and hand it your `data`; internally it renders the composable [Table](/components/data-display/table-v2/) (`Table.Root` / `Header` / `Body` / `Row` / `Head` / `Cell`, plus a `Footer` for pinned rows).

```tsx
<DataTable
  columns={columns}
  data={data}
  getRowId={(row) => row.id}
  enableRowSelection
  enableExpanding
  currentSorting={sorting}
  onSortingChange={setSorting}
/>
```

- **Columns** — each `ColumnDef` provides a `header`, an `accessorKey` (or `accessorFn`), and an optional `cell` renderer for custom content. Nest a `columns` array on a parent column for grouped headers.
- **Injected columns** — enabling features prepends columns for you: `enableRowSelection` adds a leading checkbox column (with a select-all checkbox in the header), and `enableExpanding` adds an expander chevron column (detail-panel mode) or an inline chevron on the first column (tree mode via `getSubRows`).
- **Expansion** — `renderSubComponent` renders a full-width detail panel beneath an expanded row; `getSubRows` instead renders child rows as indented rows in the same columns. Providing `getSubRows` switches to tree mode and ignores `renderSubComponent`.
- **Sorting** — sorting is **manual by default** (`manualSorting` defaults to `true`): clicking a sortable header calls `onSortingChange` with the new `SortingState`, and you sort `data` yourself (e.g. on the server). Set `manualSorting={false}` to let the table sort in place.
- **Pagination** — pass `paginationProps` to render a [Pagination](/components/navigation/pagination/) bar beneath the table.
- **Sticky / pinned** — `stickyHeader` + `maxHeight` render the table in a scroll viewport with sticky headers; `columnPinning` pins columns to the sides; `rowPinning.bottom` renders a single bottom-pinned row in a `<tfoot>`.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Provide a stable `getRowId` so selection, expansion, and pinning state track the right rows as data changes.
- Give every column a unique `id` when you use `visibleColumns`, column filters, or grouped headers.
- Keep custom `cell` renderers lightweight and consistent down a column so rows stay scannable.
- Use `getIsRowDisabled` (rather than filtering data out) when a row should be visible but not actionable.

**Don't**

- Don't forget to actually sort `data` when using the default manual sorting — the table won't reorder rows for you unless you set `manualSorting={false}`.
- Don't pin more columns than the layout can spare; leave enough scrollable width for the rest.
- Don't rely on row color or a status theme alone to convey meaning — keep the value itself explicit in the cell.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Write column headers as short nouns in sentence case ("Created at", "Year total").
- Keep cell content concise; use a custom `cell` renderer for badges or formatting rather than cramming markup into the data.
- Use a consistent format for dates and numbers within a column so sorting and scanning behave predictably.

## Accessibility

`DataTable` renders through the semantic [Table](/components/data-display/table-v2/) primitives, so it produces a real HTML `<table>` with `<thead>`, `<tbody>`, and (for pinned rows) `<tfoot>`.

### Keyboard

- The injected controls are keyboard-operable: the select-all and per-row checkboxes are focusable and toggle with **Space**, and the expander is a real [Button](/components/actions/button/) that activates with **Enter**/**Space**.
- Row selection checkboxes stop click propagation, so toggling a checkbox doesn't also fire the row's `onRowClick`.

### Labeling

- The injected checkboxes carry built-in accessible names — "Select all rows" on the header checkbox and "Select row" on each row — and the expander button is labeled "Toggle Row Expanded".
- Provide a meaningful `header` for every column so each column is announced.

### Focus & states

- Checkboxes and the expander use the standard focus ring. Disabled rows (`getIsRowDisabled`) drop to reduced opacity and a not-allowed cursor, and can't be clicked, selected, or expanded; the select-all checkbox skips them.

### Known limitations

- **Sort state isn't announced.** Sortable headers render a sort icon but set no `aria-sort`, so screen-reader users aren't told the current sort direction.
- **Sorting is mouse-driven.** The sortable header is a clickable `<th>` with no keyboard affordance of its own, so the sort can't be toggled from the keyboard — provide an alternative control if keyboard sorting matters.
- **Selected state is presentational.** Row selection styling comes from the [Table](/components/data-display/table-v2/) `selected` styling; the accessible selected state lives on the row's checkbox, not on the `<tr>` (no `aria-selected`).
- **A pinned total row appears on every page.** `keepPinnedRows` stays at TanStack's default, so a bottom-pinned row shows on every page — intended for totals, surprising for other rows. If you use row selection, exclude a synthetic totals row via `getRowCanSelect`.
