The `Draggable Card` component provides a powerful way to display and interact with cards, featuring drag and drop functionality. Built using dnd-kit, it offers a comprehensive solution for complex drag and drop interactions.

## Installation

```typescript jsx
import { DraggableCard, DraggableCardList, CardData } from '@harnessio/ui/components'

// Define your cards
const [cards, setCards] = useState<CardData[]>([
  {
    id: '1',
    title: 'First Card',
    description: 'This is the first card description',
    disableDragAndDrop: false // Optional: disable dragging for this card
  },
  {
    id: '2',
    title: 'Second Card',
    description: 'This is the second card description'
  }
])

// Use the DraggableCardList to render and manage the cards
return (
  <DraggableCardList
    cards={cards}
    setCards={setCards}
  />
)
```

Both `title` and `description` accept React components, not just strings, so you can render richer content:

```typescript jsx
const [cards, setCards] = useState<CardData[]>([
  {
    id: '1',
    title: (
      <div className="flex items-center justify-between w-full">
        <span>Card with Custom Title</span>
        <IconV2 name="settings" size="sm" />
      </div>
    ),
    description: (
      <div className="space-y-cn-xs">
        <p>This card has a custom description component</p>
        <Button>Action Button</Button>
      </div>
    )
  }
])
```

## Anatomy

The draggable card system is two components working together:

```typescript jsx
// Individual card component
<DraggableCard
  id="unique-id"
  title="Card Title"
  description="Card Description"
  disableDragAndDrop={false}
/>

// List component that manages multiple cards
<DraggableCardList
  cards={cardsArray}
  setCards={setCardsFunction}
/>
```

- **DraggableCardList** — the container you'll usually reach for. It owns the drag context (dnd-kit's `DndContext` + `SortableContext`), renders each entry in `cards` as a `DraggableCard`, and calls `setCards` with the new order when a drag ends. `listGap` controls the spacing between cards.
- **DraggableCard** — a single [Card](/components/data-display/card/) with a grip handle. By default (`gripPosition="inside"`) the grip sits inline at the start of the title row; `gripPosition="outside"` moves it to the left of the card for a cleaner surface. Setting `disableDragAndDrop` on a card makes it static.
- **Grip handle** — a `grip-dots` icon that shows a grab cursor; it's the drag affordance dnd-kit's pointer sensor listens to.
- **Sticky header** — passing `header` renders content above the list; adding `sticky` wraps the whole thing in a [`StickyListSection`](/components/utilities/sticky-list-section) so the header pins while the list scrolls.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Give every card a stable, unique `id` — reordering relies on it.
- Use `gripPosition="outside"` when the card content is dense or already has its own actions, so the drag affordance stays distinct.
- Reach for `sticky` + `header` when a reorderable list lives inside a scrollable drawer or panel and the group needs a label.
- Set `disableDragAndDrop` on cards that must stay in place rather than hiding the grip yourself.

**Don't**

- Don't put the only copy of a critical action behind drag — provide buttons (like the remove button in the examples) for anything a keyboard or touch user must reach.
- Don't nest draggable lists so deeply that it's unclear which list an item belongs to.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Keep card titles short and scannable; a reorderable list is easier to manage when each row reads at a glance.
- Put secondary details in `description`, and keep row actions (remove, settings) compact and clearly labeled with tooltips.

## Accessibility

Reordering is powered by dnd-kit. The list is configured with a pointer sensor, so dragging works with mouse and touch.

### Labeling

- The grip is an icon-only affordance. Any interactive content you place in a card (buttons, links) must carry its own accessible label — the examples use `tooltipProps` on the remove buttons for this.

### Focus & states

- While a card is being dragged it dims (reduced opacity) and lifts above its siblings, giving a clear visual cue for the item in motion.

### Known limitations

- **Reordering is pointer/touch-only.** The list registers a pointer sensor but no keyboard sensor, so cards can't be reordered from the keyboard. Where order matters for keyboard or assistive-technology users, provide an alternative way to change it (for example, up/down controls).

### CardData

The interface for the card data objects used by the `DraggableCardList` component. It extends the [Card](/components/data-display/card/) root props (minus `title` / `children`).

```typescript
interface CardData {
  id: string;
  title: string | React.ReactNode;
  description?: string | React.ReactNode;
  disableDragAndDrop?: boolean;
  gripPosition?: "inside" | "outside";
  // ...plus Card root props such as size, className
}
```
