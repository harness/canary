The `StackedList` component provides a way to display entities in a vertically stacked list format. It supports flexible item rendering, integration with links or actions, and customizable layouts for presenting structured data consistently.

It is composed of several subcomponents such as `StackedList.Root`, `StackedList.Header`, `StackedList.Item`, and `StackedList.Field` to offer a structured and customizable interface.

      <StackedList.Header>
        <StackedList.Field title="Title" />
      </StackedList.Header>
      <StackedList.Item
        thumbnail={<IconV2 name="connectors" size="xs" />}

## Variations

### Item paddings

The `StackedList.Item` can receive different paddings through the `paddingX` and `paddingY` props to match your design solution.

They support the following values: `4xs`, `3xs`, `2xs`, `xs`, `sm`, `md`, `lg`, `xl`, `2xl`, `3xl`, `4xl`, `0`.

<DocsPage.ComponentExample
  client:only
  contentClassName={"!block ![place-items:normal]"}
  code={`
    <StackedList.Root>
      <StackedList.Item
        paddingX="3xl"
        paddingY="2xl"
        thumbnail={<IconV2 name="connectors" size="xs" />}
        actions={<Button>Action</Button>}
        to="/"
      >
        <StackedList.Field title="Item 1" description="Description 1" />
      </StackedList.Item>
    </StackedList.Root>
`}
/>

### Linked item

The `StackedList.Item` accepts the `linkProps` and `to` props, which allow you to turn the entire item into a `link`.

If either of these props is provided, the whole item becomes clickable and navigates according to the link configuration. You can still use `links` and `buttons` inside as child elements — they will remain fully functional.

<DocsPage.ComponentExample
  client:only
  contentClassName={"!block ![place-items:normal]"}
  code={`
    <StackedList.Root>
      <StackedList.Item
        to="/"
        actions={<Button>Action</Button>}
      >
        <StackedList.Field title="Item 1" description="Description 1" />
      </StackedList.Item>
      <StackedList.Item
        linkProps={{ onClick: () => console.log('Clicked') }}
        actions={<Button>Action</Button>}
      >
        <StackedList.Field title="Item 2" description="Description 2" />
      </StackedList.Item>
    </StackedList.Root>
`}
/>

### Truncating

By default, both `title` and `description` have truncation enabled.
To disable it, pass the `disableTruncate` prop to `StackedList.Field`.

## Anatomy

All parts of the `StackedList` component can be imported and composed as required.

```typescript jsx
<StackedList.Root>
    <StackedList.Header>
        <StackedList.Field />
    </StackedList.Header>

    <StackedList.Item>
        <StackedList.Field />
        <StackedList.Field />
    </StackedList.Item>

    <StackedList.Item>
        <StackedList.Field />
    </StackedList.Item>
</StackedList.Root>
```

- **`StackedList.Root`** is the outer container. It draws the list border and rounded corners and can host pagination via `paginationProps`.
- **`StackedList.Header`** is an item that renders at the top as a heading row. It reuses the `Item` props but always has hover disabled and defaults its `paddingY` to `xs`.
- **`StackedList.Item`** is a single row. Provide `to`/`linkProps` to make the whole row a navigable link, or `onClick` to make it a button; add `thumbnail` and `actions` for leading and trailing content.
- **`StackedList.Field`** renders a `title` and/or `description` inside `Text` components for consistent typography. Use `right` to push a field to the trailing edge of the row.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Keep each item's fields consistent across the list so rows scan as a single column of information.
- Use `right` fields for secondary metadata (timestamps, counts, status) that should align to the trailing edge.
- Make the whole row navigable with `to`/`linkProps` rather than burying the primary link inside the row.

**Don't**

- Don't disable truncation everywhere — long, unbounded titles break the list's even rhythm. Reserve `disableTruncate` for rows that genuinely need the full text.
- Don't overload a row with competing actions; keep the `actions` slot to one or two clear controls.

## Accessibility

### Keyboard

- When an item is a link (`to`/`linkProps`) or a button (`onClick`), it is focusable and activates with `Enter` (and `Space` for buttons), following normal link/button semantics.
- Controls placed in `actions` remain independently focusable within the row.

### Labeling

- `StackedList` renders plain containers with no list/row roles, so the accessible name of each row comes from its visible `title`/`description` text and any labels on the controls inside it.
- Give icon-only `actions` and `thumbnail` controls their own accessible labels.

### Focus & states

- Rows show a hover affordance by default; `disableHover` removes it for non-interactive rows. Removing hover does not change focus behavior for any interactive elements inside.
