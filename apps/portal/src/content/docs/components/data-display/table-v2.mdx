The `Table` component provides a way to display tabular data. It's a set of composable parts — `Table.Root`, `Table.Header`, `Table.Body`, `Table.Footer`, `Table.Row`, `Table.Head`, `Table.Cell`, and `Table.Caption` — that map onto the native HTML table elements, so you assemble exactly the structure you need. Use this when you lay out the rows and columns yourself; reach for [Data Table](/components/data-display/data-table/) when you want a data-driven table with built-in sorting, selection, and expansion.

## Anatomy

All parts of the `Table` are imported from the `Table` object and composed together. They map directly onto the native HTML table elements:

```typescript jsx
<Table.Root>
  <Table.Caption />
  <Table.Header>
    <Table.Row>
      <Table.Head />
    </Table.Row>
  </Table.Header>
  <Table.Body>
    <Table.Row>
      <Table.Cell />
    </Table.Row>
  </Table.Body>
  <Table.Footer>
    <Table.Row>
      <Table.Cell />
    </Table.Row>
  </Table.Footer>
</Table.Root>
```

- **Root** — renders the `<table>` inside a container and a scroll viewport that scrolls horizontally when the table overflows. Rows highlight on hover by default (turn that off with `disableHighlightOnHover`). Passing `paginationProps` renders a [Pagination](/components/navigation/pagination/) bar beneath the table.
- **Header / Body / Footer** — render `<thead>`, `<tbody>`, and `<tfoot>`. Group your `Table.Row`s into these.
- **Row** — a `<tr>`. Mark it `selected` for selected styling or `disabled` to dim and de-activate it. Give it a `to` / `linkProps` (or an `onClick`) to make the whole row navigate — each cell then renders the link, and only the first interactive cell stays in the tab order.
- **Head** — a `<th>` header cell. It can show a `tooltipProps` tooltip (with a dashed underline) and a sort affordance via `sortable` / `sortDirection`. The first `Head` in a row automatically hides its leading divider.
- **Cell** — a `<td>`. Give it a `to` / `linkProps` to render its content as a link, or an `onClick` to make it a button; `disableLink` opts a cell out when its row is linked.
- **Caption** — a `<caption>` describing the table.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Always give the table a header row of `Table.Head` cells so every column is labeled.
- Pick a `size` that matches the density of the surrounding UI — `compact` for dense data views, `relaxed` when the table is the focus of the page.
- Keep a column's content type consistent down the column (numbers with numbers, dates with dates) so rows stay scannable.
- When a whole row navigates somewhere, use a linked `Table.Row` so the entire row is the target, and `disableLink` on any cell that holds its own control.

**Don't**

- Don't put unrelated interactive controls inside a linked row or cell — the link covers the cell and will swallow the click.
- Don't rely on the `selected` styling alone to convey selection; pair it with a real [Checkbox](/components/form/checkbox/) or [Radio](/components/form/radio/) in the row.
- Don't use a table for layout — use it only for genuinely tabular data.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Write header labels as short nouns in sentence case ("Display name", "Date added").
- Keep cell content concise; move secondary detail into a tooltip or a dedicated column rather than crowding a cell.
- Use a consistent, sortable-friendly format for dates and numbers across the column.

## Accessibility

`Table` renders semantic HTML table elements — `<table>`, `<thead>`, `<tbody>`, `<tfoot>`, `<tr>`, `<th>`, `<td>`, and `<caption>` — so assistive tech announces it as a table with rows and columns out of the box.

### Keyboard

- Static tables aren't interactive and don't take focus. When a cell or row is a link (via `to` / `linkProps`) or a button (via `onClick`), that control is keyboard-focusable and activates with **Enter** (and **Space** for buttons).
- For a linked row, only the first interactive cell is placed in the tab order (`tabIndex=0`) while the rest are skipped (`tabIndex=-1`), so a row is a single tab stop rather than one per cell.

### Labeling

- Column headers render as `<th>` inside `<thead>`, and `Table.Caption` renders a real `<caption>` — use it to give the table a name.
- Selection controls in a row carry their own accessible name: give each [Checkbox](/components/form/checkbox/) / [Radio](/components/form/radio/) a `label` or `aria-label` so it isn't announced bare.

### Focus & states

- Interactive cells and rows use the standard link/button focus ring. Selected rows are marked with a `data-checked` attribute and disabled rows with `data-disabled`; disabled rows drop to a not-allowed cursor and have their click handler suppressed.

### Known limitations

- **`selected` is presentational.** It only applies selected styling — it sets no `aria-selected`. The actual selected state must come from the Checkbox/Radio you place in the row.
- **Header cells set no explicit `scope`.** `Table.Head` renders a plain `<th>`; for complex tables with row headers or spanning headers, add `scope` (or `id`/`headers`) yourself so the header-to-cell associations are unambiguous.
- **Sort state is visual only.** `sortable` / `sortDirection` render a sort icon but set no `aria-sort` on the header, so the current sort isn't announced. Manage `aria-sort` yourself if the table is sortable.
- **A disabled row isn't disabled to assistive tech.** `disabled` suppresses the row's own `onClick` and dims it, but doesn't set `aria-disabled` on any controls inside the row — disable those controls directly if needed.
