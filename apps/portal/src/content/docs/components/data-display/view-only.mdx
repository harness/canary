The `ViewOnly` component displays data as read-only label-value pairs. It supports single-column and responsive two-column layouts, horizontal or vertical item layouts, loading states, and custom React content for any value.

<DocsPage.ComponentExample
  client:only
  code={`<ViewOnly
    title="User Details"
    data={[
      { label: "Name", value: "John Doe" },
      { label: "Email", value: "john.doe@example.com" },
      { label: "Role", value: "Administrator" },
      { label: "Status", value: "Active" }
    ]}
  />`}
/>

## Variations

### Single column layout

Force a single-column layout regardless of container width with `layout="singleColumn"`.

<DocsPage.ComponentExample
  client:only
  code={`<ViewOnly
    title="Contact Information"
    layout="singleColumn"
    data={[
      { label: "Phone", value: "+1 (555) 123-4567" },
      { label: "Address", value: "123 Main Street, City, State 12345" },
      { label: "Website", value: "https://example.com" }
    ]}
  />`}
/>

### Two-column layout

By default the component uses a responsive two-column layout when the container is wide enough (≥800px), automatically splitting the data between the two columns.

<DocsPage.ComponentExample
  client:only
  code={`<ViewOnly
    title="Project Details"
    layout="columns"
    data={[
      { label: "Project Name", value: "Canary UI" },
      { label: "Version", value: "2.0.0" },
      { label: "License", value: "MIT" },
      { label: "Repository", value: "github.com/harness/canary" },
      { label: "Last Updated", value: "January 2026" },
      { label: "Contributors", value: "42" }
    ]}
  />`}
/>

### Loading state

Display skeleton placeholders while data is being fetched.

<DocsPage.ComponentExample
  client:only
  code={`<ViewOnly
    title="Loading Data"
    isLoading
    data={[
      { label: "Field 1", value: "Value 1" },
      { label: "Field 2", value: "Value 2" },
      { label: "Field 3", value: "Value 3" }
    ]}
  />`}
/>

### Empty values

When a value is empty, `null`, or `undefined`, the component displays "empty" in a disabled style.

<DocsPage.ComponentExample
  client:only
  code={`<ViewOnly
    title="Partial Data"
    data={[
      { label: "Name", value: "John Doe" },
      { label: "Middle Name", value: "" },
      { label: "Nickname", value: null }
    ]}
  />`}
/>

### Custom value content

Values can be any React node, allowing for custom formatting and components.

<DocsPage.ComponentExample
  client:only
  code={`<ViewOnly
    title="Custom Content"
    data={[
      { label: "Status", value: <Badge variant="success">Active</Badge> },
      { label: "Tags", value: <div className="flex gap-cn-xs"><Badge>React</Badge><Badge>TypeScript</Badge></div> },
      { label: "Description", value: <Text color="foreground-2">A longer description that wraps across multiple lines when needed.</Text> }
    ]}
  />`}
/>

### Using ViewOnlyItem directly

Use the `ViewOnlyItem` component directly for more control over layout.

<DocsPage.ComponentExample
  client:only
  code={`<Layout.Vertical gap="sm">
    <ViewOnlyItem label="Username" value="johndoe" />
    <ViewOnlyItem label="Email" value="john@example.com" />
    <ViewOnlyItem label="Loading Item" value="Loading..." isLoading />
  </Layout.Vertical>`}
/>

## Anatomy

`ViewOnly` renders an optional title above a description list of label-value pairs.

- The title renders as a heading; each entry is a `ViewOnlyItem` showing a `label` and its `value`.
- `layout` controls the column mode: `columns` (default) switches to two columns once the container measures ≥800px wide, splitting the data between them; `singleColumn` always stacks in one column.
- `itemLayout` controls each pair's own orientation: `horizontal` (default) places the label and value side by side; `vertical` stacks the label above the value.
- Pass `forceColumns` to render two columns without measuring the container.
- Each `value` accepts any React node, so you can drop in badges, links, or formatted text.

<Aside type="note">
  A falsy `value` renders the placeholder text "empty" in a disabled style. This
  is a plain falsy check, so `0` and `false` also render as "empty" — wrap those
  in a string (or a custom node) if you need them shown literally.
</Aside>

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use `ViewOnly` for read-only summaries — profile details, run metadata, settings review — where fields don't need editing.
- Keep `label` text short and consistent so the columns align cleanly.
- Reach for `layout="singleColumn"` in narrow containers (side panels, drawers) where two columns would cramp the values.

**Don't**

- Don't use `ViewOnly` for editable data — it renders values as static text, not form fields.
- Don't rely on `0` or `false` displaying literally; a falsy value shows "empty".

## Accessibility

### Labeling & semantics

- In the default `horizontal` item layout, the component renders a description list: the container is a `<dl>`, each label a `<dt>`, and each value a `<dd>`, so assistive tech reads each value as the definition of its label.
- Long string values are truncated with a native `title` tooltip exposing the full text. Custom React-node values are not truncated or titled.
- The `vertical` item layout renders labels and values as plain text rather than `<dt>`/`<dd>`; prefer the default `horizontal` layout when description-list semantics matter.
