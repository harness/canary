The `Skeleton` component is a placeholder that stands in for content while it loads, giving people a visual cue that something is on its way. It's a family of parts: a free-form `Skeleton.Box` plus pre-shaped pieces (`Avatar`, `Icon`, `Logo`, `Typography`) and composites (`Form`, `List`, `Table`) that mimic common layouts. All of them share the same shimmer animation.

<DocsPage.ComponentExample
  client:only
  code={`<div className="w-[600px] grid gap-cn-md">
    <Skeleton.Box className="w-80 h-20" />
  </div>`}
/>

## Variations

### Box

`Skeleton.Box` is a free-form rectangular placeholder. Size it with `className` (width and height) to match the shape of whatever it's standing in for.

### Form

`Skeleton.Form` is a placeholder for form fields — labels and inputs. Use `linesCount` for the number of fields and `itemProps` to tweak layout (label visibility, orientation, size).

      </div>
    </div>
  </div>`}
/>

### List

`Skeleton.List` is a placeholder for list items. Use `linesCount` for the number of rows and `hasActions` to add a trailing action placeholder.

<DocsPage.ComponentExample
  client:only
  code={`<div className="w-[600px] grid gap-cn-2xl">
    <div>
      <Skeleton.List linesCount={2} />
    </div>
    <div>
      <Skeleton.List hasActions />
    </div>
  </div>`}
/>

Use the `onlyItems` prop to render only the skeleton rows, without the wrapping `StackedList.Root`.

> Note: Don't forget to add the `cn-skeleton-list` className to the parent `StackedList.Root` for correct styling.

<DocsPage.ComponentExample
  client:only
  code={`<div className="w-[600px] grid gap-cn-2xl">
    <StackedList.Root className='cn-skeleton-list'>
      <StackedList.Header>
        <StackedList.Field title="Header" />
      </StackedList.Header>

      <Skeleton.List linesCount={2} onlyItems />
    </StackedList.Root>

  </div>`}
/>

### Table

`Skeleton.Table` is a placeholder for tables. Use `countRows` and `countColumns` for the grid size; a header row is shown by default (hide it with `hideHeader`).

## Anatomy

`Skeleton` is a set of placeholder primitives that share one shimmer animation. Reach for the part that matches the shape of the content being loaded:

```tsx
<Skeleton.Box className="w-[400px] h-[80px]" />
```

- **`Skeleton.Box`** — the base primitive: a plain rectangle you size yourself with `className`. Everything else is built on it.
- **`Skeleton.Avatar` / `Skeleton.Icon` / `Skeleton.Logo`** — pre-shaped placeholders that follow the avatar, icon, and logo size scales.
- **`Skeleton.Typography`** — a text-line placeholder whose height tracks a `Text` typography variant, so swapping in the real text doesn't shift the layout.
- **`Skeleton.Form` / `Skeleton.List` / `Skeleton.Table`** — composites that assemble several boxes into common layouts (fields, rows, and a grid).

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Match the skeleton to the real layout — same rough size, shape, and count — so the swap to loaded content is calm rather than jarring.
- Use the composite parts (`Form`, `List`, `Table`) when you're loading a known structure; reach for `Box` only for one-off shapes.
- Show skeletons for the initial load of content you can't render yet; swap them for real content as soon as it arrives.

**Don't**

- Don't leave skeletons up indefinitely — if a request fails or stalls, show an error or empty state instead.
- Don't use a skeleton for quick actions where a spinner or inline loading state reads more clearly.

## Accessibility

### Focus & states

- Skeletons are purely visual: a shimmer animation loops while they're mounted, and they add no roles, interactivity, or focus targets.

### Known limitations

- Skeletons carry **no** built-in `aria-busy`, `role="status"`, or `aria-hidden`. Communicate the loading state yourself on the surrounding region — for example, set `aria-busy` on the container while it loads, or expose a visually-hidden "Loading…" message in a live region — so screen-reader users know content is on its way.
