`toast` is an imperative API for showing transient notifications. You call it from anywhere in your app, and the `Toaster` component — mounted once at the root — renders the result. To show a simple toast, call the `toast` function.

<DocsPage.ComponentExample
  client:only
  code={`
    <Button
      onClick={() =>
        toast({
          title: 'Toast title',
          description: Array.from({ length: Math.floor(Math.random() * 1000) + 1 })
            .map(() => 'a')
            .join(''),
          options: {
            duration: 3000,
            action: {
              label: 'Undo',
              onClick: () => {
                console.log('Undo')
              }
            }
          }
        })
      }
    >
      Show toast
    </Button>`}
/>

## Toast types

`toast` can show different types of toasts:

- Default toast — `toast`
- Success toast — `toast.success`
- Danger toast — `toast.danger`
- Info toast — `toast.info`
- Loading toast — `toast.loading`
- Promise toast — `toast.promise`

### Loading toast

<Aside type="caution">
  A loading toast has no close button and cannot be dismissed by the user. Close
  it programmatically with `toast.dismiss`, passing the toast id.
</Aside>

<DocsPage.ComponentExample
  client:only
  code={`
    <Button
      onClick={() => {
        const _toastId = toast.loading({
          title: 'Loading data...',
          options: {
            action: {
              label: 'Close',
              onClick: () => {
                toast.dismiss(_toastId)
              }
            }
          }
        })
      }}
    >
      Show loading toast
    </Button>
        `}
/>

### Promise toast

Promise toast accepts a **promise** as its **first argument** and an **options object** as its **second argument**.

<Aside type="caution">
  A promise toast closes automatically 7 seconds after the promise settles
  (resolves or rejects).
</Aside>

<DocsPage.ComponentExample
  client:only
  code={`
() => (
  <Button
    onClick={() => {
      const _toastId = toast.promise(new Promise((resolve, reject) => {
        const random = Math.random()
        setTimeout(() => {
          if (random > 0.5) {
            resolve('Promise resolved')
          } else {
            reject('Promise rejected')
          }
        }, 5000)
      }), {
        loadingMessage: 'Promise in progress',
        successMessage: 'Promise resolved successfully',
        errorMessage: 'Promise rejected',
        options: {
          action: {
            label: 'Action',
            onClick: () => {
              console.log('Action')
              toast.dismiss(_toastId)
            },
          },
        },
      })
    }
    }
  >
    Show promise toast
  </Button>
)
`}
/>

## Behavior

- At most **3 toasts** are visible at a time; additional toasts queue behind them.
- If `duration` is not provided, a toast closes automatically after **10 seconds**.
- A toast shows a close button unless `dismissible` is set to `false` in `options`. By default `dismissible` is `true`.
- Add an action button by providing `action` in `options`. Clicking it runs the `action` callback but does **not** close the toast — call `toast.dismiss` inside the callback if you want it to.
- **Loading toasts** cannot be dismissed by the user; close them with `toast.dismiss(id)`.
- **Promise toasts** close automatically 7 seconds after the promise settles.
- Loading and promise toasts cannot display a `description`.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use the type that matches the message: `success`/`danger` for outcomes, `info` for neutral notices, `loading`/`promise` for in-progress work.
- Keep `title` short and put detail in `description`.
- Provide an `action` (e.g. "Undo", "View details") when there's a meaningful next step.

**Don't**

- Don't use a toast for critical information a user must not miss — it's transient and auto-dismisses.
- Don't stack many toasts at once; only 3 show, and the rest queue.

## Accessibility

### Labeling & semantics

- Toasts are announced by the `Toaster`'s live region, so screen-reader users hear new notifications without moving focus.
- Because toasts disappear on a timer, don't rely on them alone to convey information a user needs to act on — pair important states with persistent UI.
