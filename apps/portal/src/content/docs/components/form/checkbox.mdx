The `Checkbox` component provides a customizable, accessible checkbox input. It's built on top of the [Radix UI Checkbox](https://www.radix-ui.com/primitives/docs/components/checkbox) primitive with additional styling, and can render an optional label and caption alongside the box.

## Installation

```typescript jsx
import { Checkbox } from "@harnessio/ui/components";

function Example() {
  const [checked, setChecked] = React.useState(false);

  return (
    <Checkbox
      id="accept-terms"
      checked={checked}
      onCheckedChange={setChecked}
      label="Accept terms and conditions"
      caption="You must accept terms and conditions to proceed."
    />
  );
}
```

The checkbox works controlled (with `checked` + `onCheckedChange`) or uncontrolled (with `defaultChecked`). Set `checked="indeterminate"` for a partial-selection state.

## Anatomy

`Checkbox` is a single component — you configure it entirely through props, not by composing parts:

```typescript jsx
<Checkbox
  checked={checked}
  onCheckedChange={setChecked}
  label="Accept terms and conditions"
  caption="You must accept terms and conditions to proceed."
/>
```

Internally it renders:

- **The box** — the Radix checkbox itself, with an indicator that shows a check for the checked state and a minus for `indeterminate`. It picks up the `error` styling when `error` is set.
- **Label** — when you pass `label`, a [Label](/components/form/label/) is rendered and wired to the box with `htmlFor`, so clicking the text toggles the checkbox. A stable `id` is generated automatically if you don't supply one.
- **Caption** — when you pass `caption`, a helper line renders beneath the label.

The label and caption block only appears if you pass `label` or `caption`; otherwise just the box renders (give it an `aria-label` in that case — see accessibility).

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Give every checkbox an accessible name — a `label` for the common case, or an `aria-label` when the box stands alone.
- Use the `indeterminate` state for a parent checkbox that summarizes a mix of checked and unchecked children.
- Keep the `label` to a short, clear statement of what checking the box means, and use `caption` for the supporting detail.

**Don't**

- Don't use a checkbox for mutually exclusive choices — use [Radio](/components/form/radio/) instead.
- Don't rely on the `error` styling alone to communicate a problem; pair it with a visible, associated message (see the accessibility notes).
- Don't write labels as questions ("Accept terms?"); phrase them as the affirmative action ("Accept terms and conditions").

- Write the label as a positive statement of what checking does, in sentence case.
- Keep the caption to one short line of supporting guidance or a format/requirement note.

## Accessibility

`Checkbox` is built on the Radix Checkbox primitive, so it exposes proper checkbox semantics and keyboard support.

### Keyboard

- The box is in the tab order and toggles with **Space**.
- Disabled checkboxes are skipped by keyboard navigation.

### Labeling

- When you pass `label`, it's associated with the box via `htmlFor`/`id` (an `id` is auto-generated if you don't provide one), so the text is both clickable and announced as the checkbox's name.
- The `indeterminate` state is exposed as `aria-checked="mixed"` and shown with a minus icon, distinguishing it from both checked and unchecked.

### Focus & states

- The box shows the standard keyboard focus ring, and disabled/error states have distinct styling.

### Known limitations

- **A checkbox with no `label` has no accessible name.** When you omit `label`, only the box renders, so you must pass an `aria-label` (or `aria-labelledby`) yourself — those forward to the underlying checkbox. Without one, screen-reader users hear an unlabeled checkbox.
- **`error` is styling only.** The `error` prop turns the box red but sets no `aria-invalid` and isn't linked to any message. The `caption` is visible but not wired up as `aria-describedby`, so an error conveyed through color/caption alone won't reach assistive tech. Set `aria-invalid` and associate an error message yourself, or use the form-field components that handle that wiring.
- **`showOptionalLabel` is inverted, and its indicator is decorative.** By default no required marker shows; passing `showOptionalLabel={false}` renders a required asterisk. That asterisk is `aria-hidden`, so it's a visual cue only — required state isn't announced. Mark the field required through your form validation as well.
