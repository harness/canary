`FilterFieldTypes.DateRange` integrates the standalone [`DateRangePicker`](./date-range-picker/) with the filters system. It uses the same controlled semantic value, presets, timezone behavior, and optional capabilities while adding filter trigger and remove-filter behavior.

## Usage

```typescript jsx
import { useState } from 'react'
import {
  dateRangeValueParser,
  FilterField,
  FilterFieldTypes,
  type SemanticDateRangeValue,
} from '@harnessio/ui/components'

export const Filters = () => {
  const [value, setValue] = useState<SemanticDateRangeValue>()

  return (
    <FilterField
      filterOption={{
        type: FilterFieldTypes.DateRange,
        label: 'Timeframe',
        value: 'timeframe',
        parser: dateRangeValueParser,
        filterFieldConfig: {
          defaultTimeZone: 'UTC',
          weekStartsOn: 1,
        },
      }}
      removeFilter={() => setValue(undefined)}
      shouldOpenFilter={false}
      onChange={setValue}
      value={value}
    />
  )
}
```

The controlled value is the same semantic union used by the standalone picker:

- `relative` stores a live past or future rolling window.
- `calendar` stores a named period such as `last_week` or `next_month`.
- `absolute` stores fixed civil dates and optional times.

UTC is the default. The selected IANA timezone persists on every semantic value so reloading a URL or saved filter preserves local calendar boundaries. `resolveDateRange` converts the value to inclusive `from` and exclusive `to` UTC instants (`[from, to)`) when the product constructs its query.

## Configure picker capabilities

```typescript jsx
const filterFieldConfig = {
  allowFuture: true,
  enableOffset: true,
  enableExclusions: true,
  defaultTimeZone: "America/New_York",
  weekStartsOn: 1,
};
```

- Future dates are enabled by default. Set `allowFuture: false` to opt out, or pass additional constraints through `calendarProps`.
- Fixed ranges always show editable full-day endpoint times. Rolling and calendar values retain derived boundaries.
- Offset and exclusion controls are hidden unless `enableOffset` or `enableExclusions` is set. They appear only in Rolling and commit with the range through the same Apply action. Their semantic adjustment is mutually exclusive, and offsets additionally require a past/Last direction.
- After a complete fixed range, the next date click resets the range and starts a new selection.

## Queries

`onInterpretQuery` is an optional asynchronous extension point owned by the consuming product. The component provides loading and error UI but does not choose an AI/query service.

```typescript jsx
const filterFieldConfig = {
  onInterpretQuery: async (query) => {
    if (query.trim().toLowerCase() === "next month") {
      return {
        kind: "calendar",
        period: "next_month",
        timeZone: "UTC",
      };
    }
    throw new Error("Unsupported date-range query");
  },
};
```

Omit the callback to hide the search field.

## URL and saved-filter persistence

Assign `dateRangeValueParser` to the filter option's `parser`. Its versioned format round-trips semantic kind, timezone, absolute dates and times, and relative adjustments. The parser throws for invalid persisted input; use `parseDateRangeValue` directly when a non-throwing `undefined` result is preferable.

Legacy `{ from, to, preset? }` values and `{ label, value, group, getRange }` presets remain accepted to avoid breaking existing filters, but both forms are deprecated. Legacy snapshots cannot fully preserve live intent. Prefer semantic values and presets shaped as `{ id, label, group, value }`.

## Custom semantic presets

```typescript jsx
const presets = [
  {
    id: "next-14-days",
    label: "Next 14 days",
    group: "recommended",
    value: {
      kind: "relative",
      direction: "future",
      amount: 14,
      unit: "day",
      timeZone: "UTC",
    },
  },
];

const filterFieldConfig = { presets };
```

Preset values are semantic and therefore stay live. The picker applies its currently selected timezone when a user chooses a preset.
