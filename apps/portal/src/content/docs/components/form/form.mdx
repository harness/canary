The form system consists of two main components:

- `FormWrapper` — a container component that wraps form inputs, handles form submission, and sets the input layout orientation to either `vertical` or `horizontal`
- `FormInput` — a set of input components for different data types

The `FormInput` components generate fields with the correct labels, input types, validation feedback, and accessibility attributes.

## Installation

Compose a form from three pieces: a zod schema for validation, `useForm` from react-hook-form wired up with `zodResolver`, and `FormWrapper` + `FormInput.*` for the fields.

```typescript jsx
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";
import { Button, FormInput, FormWrapper } from "@harnessio/ui/components";

// ...

/**
 * 1️⃣ Define the validation schema with zod
 */
const formSchema = z.object({
  /** 💡 As a best practice, use trim() to remove whitespace from the input */
  name: z.string().trim().min(3, "Input must be at least 3 characters"),

  // 🚨 z.coerce.number() - Must be used for number fields
  // https://github.com/shadcn-ui/ui/issues/421#issuecomment-1561080201
  age: z.coerce.number().min(1, "Number must be at least 1"),
  time: z.string().optional(),
  comment: z.string().trim().min(10, "Comment must be at least 10 characters"),
});

// ...

/** 2️⃣ Infer the type from the schema */
const FormValuesType = z.infer<typeof formSchema>;

function FormWithZodAndReactHookForm() {
  /** 3️⃣ Initialize react-hook-form with zod resolver */
  const formMethods = useForm<FormValuesType>({
    resolver: zodResolver(formSchema),
    defaultValues: {
      name: "John doe",
      age: 1,
      comment: "Lorem ipsum",
    },
  });

  /** 4️⃣ Extract register and handleSubmit from formMethods */
  const { register, handleSubmit } = formMethods;

  /** 6️⃣ Handle form submission */
  const onSubmit = (data: FormValuesType) => {
    // ...
  };

  /** 5️⃣ Use FormWrapper with formMethods and onSubmit */
  return (
    <FormWrapper {...formMethods} onSubmit={handleSubmit(onSubmit)} orientation="vertical">
      <FormInput.Text {...register("name")} label="Name" />
      <FormInput.Number {...register("age")} label="Age" />
      <FormInput.Time {...register("time")} label="Meeting Time" />
      <FormInput.Textarea {...register("comment")} label="Comment" />
      <Button type="submit">Submit</Button>
    </FormWrapper>
  );
}
```

## Anatomy

A form is composed of a `FormWrapper` container and one or more `FormInput.*` fields, driven by react-hook-form and validated with zod.

```tsx
<FormWrapper {...formMethods} onSubmit={handleSubmit(onSubmit)}>
  <FormInput.Text {...register("name")} label="Name" />
  <FormInput.Number {...register("age")} label="Age" />
  <Button type="submit">Submit</Button>
</FormWrapper>
```

- **FormWrapper** — renders react-hook-form's `FormProvider` around a `<form>` element (`noValidate`, so validation is handled by zod, not the browser). Spread the full `useForm` return value into it so its inputs can read and write form state. It also sets the `orientation` (`vertical` by default, or `horizontal`) that every field inside inherits.
- **FormInput.\*** — the field primitives: `Text`, `Textarea`, `Number`, `Time`, `Radio`, `Checkbox`, `Select`, and `MultiSelect`. Each is bound to the form with `register("fieldName")`, and each generates its own label, input type, validation feedback, and accessibility wiring. Because they read form state from context, `FormInput.*` must be rendered inside a `FormWrapper` — using one outside throws.
- **Validation feedback** — a field's error comes from the zod resolver via react-hook-form; the input displays it automatically. For errors that don't attach to a single input (like the checkbox terms error above), render a `FormCaption theme="danger"` yourself.

### Form in a dialog

To put a form inside a [Dialog](/components/overlays/dialog/), place the `FormWrapper` inside `Dialog.Body` and give it an `id`. Put the submit button in `Dialog.Footer` with `type="submit"` and a `form` attribute matching that `id`, so the button submits the form across the dialog's body/footer boundary.

```typescript jsx
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";
import { Button, FormInput, FormWrapper, Dialog } from "@harnessio/ui/components";

// ...

/**
 * 1️⃣ Define the validation schema with zod
 */
const formSchema = z.object({
  /** 💡 As a best practice, use trim() to remove whitespace from the input */
  name: z.string().trim().min(3, "Input must be at least 3 characters"),
});

// ...

/** 2️⃣ Infer the type from the schema */
const FormValuesType = z.infer<typeof formSchema>;

function FormInDialog() {
  /** 3️⃣ Initialize react-hook-form with zod resolver */
  const formMethods = useForm<FormValuesType>({
    resolver: zodResolver(formSchema),
    defaultValues: {
      name: "John doe"
    },
  });

  /** 4️⃣ Extract register and handleSubmit from formMethods */
  const { register, handleSubmit } = formMethods;

  /** 6️⃣ Handle form submission */
  const onSubmit = (data: FormValuesType) => {
    // ...
  };

  /** 5️⃣ Use FormWrapper with formMethods and onSubmit */
  return (
    <Dialog.Root>
      <Dialog.Trigger>
        <Button iconOnly onClick={() => setOpen(true)}>
          <IconV2 name="theme" />
        </Button>
      </Dialog.Trigger>

    <Dialog.Content>
      <Dialog.Header>
        <Dialog.Title>Form</Dialog.Title>
      </Dialog.Header>

      <Dialog.Body>
        <FormWrapper id="id-form" {...formMethods} onSubmit={handleSubmit(onSubmit)}>
          <FormInput.Text {...register("name")} label="Name" />
        </FormWrapper>
      </Dialog.Body>

      <Dialog.Footer>
        <Dialog.Close>Cancel</Dialog.Close>
        <Button type="submit" form="id-form" variant="primary">Submit</Button>
      </Dialog.Footer>
    </Dialog.Content>
  </Dialog.Root>
  );
}
```

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Pass **all** of `useForm`'s return values into `FormWrapper` (spread `{...formMethods}`) — the fields depend on that context to read and write state.
- Use `z.coerce.number()` for number fields so the string value from the input is coerced before validation.
- Call `trim()` in string schemas so leading and trailing whitespace doesn't slip past a `min` length check.
- Define validation in the zod schema and let each field surface its own error, rather than wiring error messages by hand.

**Don't**

- Don't render a `FormInput.*` outside a `FormWrapper` — it reads form context and will throw.
- Don't rely on native browser validation; the form is `noValidate` and validation runs through zod.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Write labels that name the field ("Meeting time", "Age"), not an instruction.
- Keep validation messages specific and actionable ("Input must be at least 3 characters"), so people know exactly how to fix the field.
- Use captions for supplementary guidance, and reserve the danger caption for errors.

## Accessibility

`FormWrapper` renders a real `<form>` and each `FormInput.*` generates its own label, input type, and validation wiring, so fields are labeled and their errors are associated automatically.

### Keyboard

- Fields are standard inputs: **Tab** / **Shift+Tab** move between them, and the submit `Button` activates with **Enter** or **Space**.
- Radio groups move between options with the **Arrow** keys; checkboxes toggle with **Space**.

### Labeling

- Each field's `label` is associated with its control, and validation messages are tied to the field so assistive tech announces the error with the input.
- For errors that aren't bound to a single field, render a `FormCaption` so the message is still visible and read in context.

### Focus & states

- Invalid fields show their error state and message inline; keep the submit button's `disabled`/submitting state in sync with `formState` so the form's status is clear.
