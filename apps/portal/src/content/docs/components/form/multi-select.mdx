The `MultiSelect` component lets users select multiple options from a dropdown list. Selected options appear as removable tags, and users can optionally create new options by typing. It's suited to scenarios where more than one value is needed — tags, frameworks, labels, and similar.

          { key: 'Vue', id: 'vue' },
        ]}

      />

## Variations

### Disallow creation

The `MultiSelect` component accepts an optional `disallowCreation` prop.
When set to `true`, it disables the ability to add new items that are not part of the existing options list.

## Installation

```tsx
import { MultiSelect, MultiSelectOption } from "@harnessio/ui/components";
import { useState } from "react";

// Basic usage with controlled component
const MyComponent = () => {
  const [selected, setSelected] = useState<MultiSelectOption[]>([]);

  return (
    <MultiSelect
      label="Select frameworks"
      placeholder="Select options..."
      options={[
        { key: "react", id: "react" },
        { key: "vue", id: "vue" },
        { key: "angular", id: "angular" },
      ]}
      value={selected}
      onChange={setSelected}
    />
  );
};
```

## Anatomy

`MultiSelect` is built on the `cmdk` command primitive. It renders a labeled input with a dropdown of `options`; chosen items show as removable tags inside the field.

```tsx
<MultiSelect
  label="Frameworks"
  options={[{ key: "React", id: "react" }]}
  value={selected}
  onChange={setSelected}
/>
```

- **Options** — each option is a `MultiSelectOption` with a required `id` and `key`. `key` is used as the tag label and the default dropdown label; pass `label` to customize the dropdown row (selected tags still use `key`).
- **Controlled vs uncontrolled** — pass `value` + `onChange` for a controlled selection; omit `value` and seed with `defaultValue` (default `[]`) for uncontrolled use.
- **Creating options** — typing a value and pressing <kbd>Enter</kbd> creates a new option (comma-separated input creates several). `creationValueMode` controls parsing: `keyValue` (default) splits `key:value` pairs, `literal` uses the raw text as-is. Set `disallowCreation` to turn this off — the empty dropdown then shows "No results found" instead of the creation hint.
- **Validation & theme** — `theme` (`default` / `danger` / `warning`) styles the field. A non-empty `error` string forces the `danger` theme and shows the error caption; a non-empty `warning` forces `warning`. Otherwise `caption` shows as helper text.
- **Search** — filtering is client-side by default (matched against `key`). Provide `searchQuery` + `setSearchQuery` to drive search externally (e.g. server-side); the built-in filter is then bypassed.
- **Layout & label** — `label`, `caption`, `optional`, and tooltip (`tooltipContent` / `tooltipProps`) render around the field. `orientation` (`vertical` default / `horizontal`) sets whether the label sits above or beside the input.
- **Other states** — `disabled` disables the field and hides tag remove icons; `isLoading` shows a loading skeleton inside the open dropdown; `maxSelected` isn't supported.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Give every option a stable, unique `id` — removal, replacement, and change detection key off it.
- Use `disallowCreation` when the value set is fixed (a known enum) and free-form entries would be invalid.
- Prefer `error` / `warning` strings over setting `theme` directly, so the validation message and the color stay in sync.

**Don't**

- Don't use `MultiSelect` for a single choice — reach for Select instead.
- Don't overload the list with hundreds of ungrouped options without search; wire up `searchQuery` / `setSearchQuery` for large, server-backed sets.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Write a `label` that names what's being collected ("Frameworks", "Labels") and a `placeholder` that hints at the action ("Select frameworks you like…").
- Keep option `key`s short and human-readable — they're what users see as tags.

## Accessibility

### Keyboard

- <kbd>Backspace</kbd> / <kbd>Delete</kbd> on an empty input removes the last
  selected tag.
- <kbd>Enter</kbd> creates an option from the typed text (unless
  `disallowCreation` is set).
- <kbd>Escape</kbd> blurs the input and closes the dropdown.

### Labeling

- `label` is tied to the input via `htmlFor`/`id`, so assistive tech announces the field name and clicking the label focuses the input.
- `placeholder` is also applied as the field's `aria-label`.

### Focus & states

- The dropdown opens on input focus and closes on outside click or blur. Selected tags expose a remove control (hidden when `disabled`).

### Known limitations

- **Not a semantic combobox/listbox.** The field container uses `role="textbox"` rather than the ARIA combobox/listbox pattern — it doesn't set `aria-expanded`, `aria-activedescendant`, or listbox roles. Screen-reader users may not get the full "N of M, expanded" combobox experience.

### MultiSelectOption

```typescript
interface MultiSelectOption {
  id: string | number; // Required — unique identifier for the option
  key: string; // Required — tag label and default dropdown label
  value?: string; // Optional — secondary value for key-value pairs
  label?: ReactNode; // Optional — custom dropdown content; selected tags still use `key`
  icon?: IconV2NamesType; // Optional — icon shown in the dropdown item
  title?: string; // Optional — title attribute for the option
  disable?: boolean; // Optional — disables the option in the dropdown
  theme?: TagTheme; // Optional — tag color for the selected item
  onReset?: () => void; // Optional — called when the option is removed
}
```
