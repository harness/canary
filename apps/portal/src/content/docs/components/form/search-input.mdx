`SearchInput` is a text input tuned for search: a leading search icon, a built-in 300ms debounce so callbacks don't fire on every keystroke, and optional match-navigation controls.

The example below tracks the current value with React state.

<DocsPage.ComponentExample client:only code={`() => {
  // Using useState hook to track search value
  const [searchValue, setSearchValue] = React.useState("");

return (

<div className="flex flex-col gap-cn-xl min-w-[400px]">
  <div className="mb-cn-xs w-full font-bold mt-cn-xl">Search with State:</div>
  <SearchInput
    placeholder="Type to search..."
    onChange={(value) => setSearchValue(value)}
  />
  <div className="rounded-cn-3 border p-cn-sm">
    <div className="text-cn-size-2 font-medium underline underline-offset-2">
      Current Search Value:
    </div>
    <p className="mt-cn-3xs font-body-code text-cn-size-2">
      {searchValue || "(empty)"}
    </p>
  </div>
</div>

## Variations

### With navigation

Set `showPrevNextButtons` to add match-navigation controls. Previous, next, and clear buttons appear once there's text in the field.

**Navigation:**

- Click the **↑** button or press **Shift+Enter** to go to the previous result
- Click the **↓** button or press **Enter** to go to the next result
- Click the **×** button to clear the search
- Click the **⌘F** badge or press **⌘F** (Mac) / **Ctrl+F** (Windows/Linux) to focus the search input

<DocsPage.ComponentExample client:only code={`() => {
  const [searchValue, setSearchValue] = React.useState("");
  const [currentIndex, setCurrentIndex] = React.useState(0);
  const searchInputRef = React.useRef(null);
  
  // Mock search results for demonstration
  const mockResults = searchValue ? Array.from({ length: 1000 }, (_, i) => \`Result \${i + 1}\`) : [];
  const totalResults = mockResults.length;

const handlePrev = () => {
setCurrentIndex((prev) => (prev > 0 ? prev - 1 : totalResults - 1));
};

const handleNext = () => {
setCurrentIndex((prev) => (prev < totalResults - 1 ? prev + 1 : 0));
};

const handleEnter = (text, reverse) => {
if (reverse) {
handlePrev();
} else {
handleNext();
}
};

const handleShortcutClick = () => {
searchInputRef.current?.focus();
};

// Keyboard shortcut handler
React.useEffect(() => {
const handleKeyDown = (e) => {
if ((e.metaKey || e.ctrlKey) && e.key === 'f') {
e.preventDefault();
searchInputRef.current?.focus();
}
};
window.addEventListener('keydown', handleKeyDown);
return () => window.removeEventListener('keydown', handleKeyDown);
}, []);

return (

<div className="flex flex-col gap-cn-xl min-w-[400px]">
  <div className="mb-cn-xs w-full font-bold mt-cn-xl">Search with Navigation:</div>
  <SearchInput
    ref={searchInputRef}
    placeholder="Type to search..."
    onChange={(value) => {
      setSearchValue(value);
      setCurrentIndex(0);
    }}
    showPrevNextButtons
    counter={searchValue ? \`\${currentIndex + 1}/\${totalResults}\` : ""}
    onPrev={handlePrev}
    onNext={handleNext}
    onEnter={handleEnter}
    suffix={
      <button 
        onClick={handleShortcutClick}
        className="mr-cn-2xs cursor-pointer bg-transparent border-0 p-0"
      >
        <Shortcut>⌘F</Shortcut>
      </button>
    }
  />
  <div className="rounded-cn-3 border p-cn-sm">
    <div className="text-cn-size-2 font-medium underline underline-offset-2">
      Current Result:
    </div>
    <p className="mt-cn-3xs font-body-code text-cn-size-2">
      {searchValue && totalResults > 0 ? mockResults[currentIndex] : "(no results)"}
    </p>
  </div>
</div>
) }`} />

## Anatomy

`SearchInput` is a single input with a leading search icon. It manages its own value internally — read changes through `onChange` (which receives the string value, debounced), and drive a controlled value with `searchValue`.

```tsx
<SearchInput
  placeholder="Type to search..."
  onChange={(value) => setQuery(value)}
/>
```

- **Debounce** — `onChange` is debounced 300ms by default. Pass a number to change the delay, or `false` to fire on every keystroke.
- **Navigation** — with `showPrevNextButtons`, previous / next / clear buttons appear when there's text. Wire `onNext` / `onPrev` (or a single `onEnter(text, reverse)`), and show progress with `counter`.
- **Suffix** — use `suffix` for a trailing affordance, such as a keyboard-shortcut badge.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Keep the default debounce for live-filtering large lists or issuing network requests; only lower it when instant feedback matters.
- Show a `counter` (e.g. `3/128`) whenever you enable navigation, so people know where they are in the results.
- Provide an accessible name (see Accessibility) since the field has no visible label.

**Don't**

- Don't add navigation buttons for a simple filter that has no notion of "current match".
- Don't debounce when the input drives purely local, cheap state where users expect instant response.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Use a placeholder that hints at the scope of the search ("Search pipelines…"), not just "Search".
- Keep the `counter` compact — "current/total" (`3/128`).

## Accessibility

### Keyboard

- **`Enter`** triggers `onEnter` moving forward (next match); **`Shift + Enter`** triggers it in reverse (previous match).
- The optional previous / next / clear buttons are standard buttons, reachable and activatable from the keyboard.
- **`⌘F` / `Ctrl+F` is not handled by the component.** The demo wires its own window listener; add one yourself if you want that shortcut.

### Labeling

- The field renders as a plain text input with no visible label and no built-in `aria-label`. Provide `aria-label` (or associate a label) so its purpose is announced.
- The navigation buttons carry `aria-label`s ("Previous match", "Next match", "Clear search").
