The `Select` component provides a dropdown for choosing a single value from a list of options. It supports both controlled and uncontrolled modes, clearable selections, async loading, search filtering, grouped options, and the usual form-field affordances (label, caption, error/warning).

<DocsPage.ComponentExample
  client:only
  code={`() => {
    const [value, setValue] = React.useState('banana');

    return (
      <Select
        options={[
          { label: 'Apple', value: 'apple' },
          { label: 'Banana', value: 'banana' },
          { label: 'Orange', value: 'orange' },
          { label: 'Strawberry', value: 'strawberry' },
        ]}
        value={value}
        onChange={setValue}
        placeholder="Select a fruit"
      />
    );

}`}
/>

## Variations

### Clearable selection

Set `clearable` to show a clear button when a value is selected. Clearing the field resets the value to `undefined`, calls `onChange(undefined)`, and invokes `onClear` when provided.

<DocsPage.ComponentExample
  client:only

        label="Clearable fruit selector"

          { label: 'Apple', value: 'apple' },
          { label: 'Banana', value: 'banana' },
          { label: 'Orange', value: 'orange' },
          { label: 'Strawberry', value: 'strawberry' },
        ]}
        value={value}
        onChange={setValue}
        onClear={() => console.log('Selection cleared')}
        clearable
        placeholder="Select a fruit"

## Anatomy

`Select` is a single component driven by the `options` prop — a flat list, grouped lists, or an async function that resolves options. Control the selection with `value` + `onChange`, or leave it uncontrolled with `defaultValue`.

```tsx
<Select
  options={[
    { label: "One", value: "one" },
    { label: "Two", value: "two" },
  ]}
  value={value}
  onChange={setValue}
  placeholder="Select an option"
/>
```

- **Options** can be flat (`{ label, value, disabled? }`), grouped (`{ label, options: [...] }`), or a separator (the string `'-'`). Pass a function returning a `Promise` for async loading; the component shows a spinner while it resolves.
- **Search** — set `allowSearch` to show a search box in the dropdown; the default filter matches the option label. `onSearch` is a notification callback fired with the (debounced) query — it doesn't replace the built-in filtering.
- **Form field** — `label`, `caption`, `error`, and `warning` render the surrounding form chrome; a hidden input carries the `name`/`value` for native form submission.
- **Dropdown content** — customize with `header`, `footer`, `optionRenderer`, and `contentWidth`; `onScrollEnd` fires near the bottom for infinite scroll and `onOpen` fires when the menu opens.

It's built on the `DropdownMenu` primitive rather than a native `<select>`, so the trigger opens a menu of items rather than a native option list.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use `Select` for choosing one value from a moderate-to-long list; for a few always-visible options, prefer `Radio`.
- Turn on `allowSearch` once the list gets long enough that scanning is slow.
- Set a `placeholder` that names what's being chosen ("Select a branch"), and preselect a sensible `defaultValue` when one exists.

**Don't**

- Don't use `error`/`warning` decoratively — they force the danger/warning theme and read as validation feedback.
- Don't nest deep group hierarchies; grouping is a single level of labelled sections with optional separators.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Write option labels as short, parallel phrases; reserve rich `ReactNode` labels for cases that genuinely need an icon or secondary text.
- Keep group labels ("Fruits", "Vegetables") as plain category names.

## Accessibility

### Keyboard

- The trigger is a button that opens a menu (via the `DropdownMenu` primitive): arrow keys move between items, `Enter` selects, and `Escape` closes. When `allowSearch` is on, typing in the search box narrows the list and the arrow keys still move the highlight through the filtered items.

### Labeling

- Provide a `label` (or associate your own) so the trigger has an accessible name; the label is wired to the control via `htmlFor` / `id`, and an `id` is generated when you don't pass one.
- The selected option is indicated with a checkmark in the menu.

### Focus & states

- Because it's built on a menu primitive rather than a native `listbox`/`combobox`, it uses menu semantics rather than the native selected-option model. `error` and `warning` drive the visual theme; wire them from your own validation.

type SelectOption<T = string> =
  | {
      label: string | ReactNode;
      value: T;
      disabled?: boolean;
    }
  | {
      label: string;
      options: Array<
        | {
            label: string | ReactNode;
            value: T;
            disabled?: boolean;
          }
        | "-"
      >;
    }
  | "-";
