The Layout component provides a set of flexible layout primitives for building consistent UI layouts. It includes `Flex`, `Grid`, `Horizontal`, and `Vertical` components with a clean, type-safe API.

## Flex

## Anatomy

`Layout` is a collection of four primitives — `Layout.Flex`, `Layout.Grid`, `Layout.Horizontal`, and `Layout.Vertical`. Each renders a `div` by default and takes spacing from the design-system scale.

```tsx
<Layout.Vertical gap="md">
  <Layout.Horizontal justify="between" align="center">
    {/* … */}
  </Layout.Horizontal>
</Layout.Vertical>
```

- **Flex** — a flexbox container. `direction` defaults to `row`; `align`, `justify`, and `wrap` are unset until you provide them. `grow` toggles `flex-grow`. Flex has **no default gap**.
- **Grid** — a CSS-grid container. `columns` and `rows` accept either a track string (`"2fr 1fr"`, `"auto auto"`) applied verbatim, or a number, which expands to that many equal tracks (`repeat(n, …)`). `flow` maps to `grid-auto-flow`. Grid has no `direction`/`wrap`.
- **Horizontal / Vertical** — thin wrappers around Flex that lock `direction` to `row` / `column` (it can't be overridden) and **default `gap` to `md`**. Everything else passes straight through to Flex.
- **Spacing** — `gap`, `gapX`, and `gapY` take the token scale (`none`, `4xs` … `4xl`) and map to `gap-cn-*` utilities, so spacing stays consistent with the rest of the system.
- **Polymorphism** — `as` renders a different element (e.g. `as="span"`) while keeping the same layout props.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Reach for `Horizontal`/`Vertical` for the common row/column cases — they read clearly and already default `gap` to `md`.
- Use `Grid` when you need real two-dimensional control (aligned columns and rows); use `Flex` for one-dimensional flows.
- Keep spacing on the token scale (`gap="md"`) instead of ad-hoc margins so rhythm stays consistent.

**Don't**

- Don't nest many `Flex` containers to fake a grid — use `Grid` with `columns`.
- Don't reintroduce raw pixel gaps via `className` when a `gap` token exists.

## Accessibility

Layout primitives are structural containers — they render a plain element (`div` by default) and add no roles or semantics of their own.

### Labeling

- Because these are generic containers, give meaning through the elements you place inside them (headings, landmarks, lists) or by rendering a semantic element with `as` (e.g. `as="nav"`, `as="ul"`).

### Known limitations

- **No implicit semantics.** A `Layout.*` won't announce itself as a region or list; choose the right element via `as` when structure matters to assistive tech.
