The `Page` component provides the header + content structure that sits inside the [Sandbox Layout](/components/foundations/sandbox-layout) main area. It's a compound component — `Page.Root` establishes the page context, `Page.Header` (or `Page.HeaderV2`) standardizes the title, back navigation, and actions, and `Page.Content` holds the scrollable body.

`Page.Header` composes a back link, an icon or logo, the page title, a description, and header-right actions into a single standardized header.

<DocsPage.ComponentExample
  client:only
  code={`
    <div className="w-full">
      <Page.Header
        title="Pipelines"
        iconName="empty-page"
        description="Define, run, and monitor your CI/CD pipelines."
        backLink={{ linkText: 'Back to project', linkProps: { to: '#' } }}
        actions={
          <>
            <Button variant="outline">Settings</Button>
            <Button>New pipeline</Button>
          </>
        }
      />
    </div>
`}

## Variations

### Header with tabs (Page.HeaderV2)

`Page.HeaderV2` is the newer header variant that supports a title row plus a tab strip for section navigation. The tabs are router-driven — each `value` is a route the tab links to, and the active tab is derived from the current URL.

## Installation

import { Page } from "@harnessio/ui/components";

<Page.Root>
  <Page.Header
    title="Pipelines"
    backLink={{ linkText: "Back to project", linkProps: { to: "/project" } }}
    actions={<Button>New pipeline</Button>}
  />
  <Page.Content>{/* page body */}</Page.Content>
</Page.Root>;

## Anatomy

`Page` is a compound component. Wrap the page in `Page.Root`, put a header (`Page.Header` or `Page.HeaderV2`) at the top, and render the body inside `Page.Content`.

```tsx
<Page.Root>
  <Page.Header
    title="Pipelines"
    backLink={{ linkText: "Back to project", linkProps: { to: "/project" } }}
  >
    {/* optional content rendered below the description */}
  </Page.Header>

  <Page.Content>{/* page body */}</Page.Content>
</Page.Root>
```

- **`Page.Root`** — establishes the header + content context inside the Sandbox Layout main area. Pass `scrollable` to make the content region scroll (and the header stick).
- **`Page.Header`** — the standard header: `title` (rendered as an `<h1>` when it's a string), optional `iconName` / `logoName`, `description`, `backLink`, and header-right `actions`. Any `children` render below the description.
- **`Page.HeaderV2`** — the header variant with a `title` row plus a router-driven `tabs` strip; also takes `breadcrumbs`, `description`, `iconName`, and `actions`.
- **`Page.Content`** — the page body region; fills the remaining space, and scrolls when `Page.Root` is `scrollable`.

In `Page.HeaderV2`, each entry in `tabs` links to a route — the active tab is resolved from the current URL, and `exact` controls exact-path matching (used for the index route).

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use one `Page.Header` (or one `Page.HeaderV2`) per page, at the top of `Page.Root`, so the title and back navigation are consistent across screens.
- Reach for `Page.HeaderV2` when the page has sub-sections that map to routes; use `Page.Header` for a single-view page.
- Put page-level actions in the header's `actions` slot rather than inside the content.

**Don't**

- Don't nest a second header inside `Page.Content` — the header belongs directly under `Page.Root`.
- Don't use the header tabs for in-page state that isn't reflected in the URL; they're built for route navigation.

## Accessibility

### Keyboard

- `Page.HeaderV2` tabs are rendered as router links, so they're reachable and activatable with standard link keyboard behavior; the active tab follows the URL.

### Labeling

- When `title` is a string, both `Page.Header` and `Page.HeaderV2` render it as a semantic `<h1>`, giving each page a top-level heading. If you pass a non-string node, provide the heading semantics yourself.
- `backLink` renders a real link labeled by `linkText` — keep that text descriptive of where it goes.

### Focus & states

- In a `scrollable` `Page.Root`, the header becomes sticky (pinned to the top with a solid background) while the content scrolls beneath it.
