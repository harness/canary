The `SandboxLayout` component is the outer scaffold used by most full-page screens. It provides a stable grid shell with an optional left navigation panel, a fixed header, and a scrollable main content area. It's a set of compound layout primitives — you compose the pieces you need.

Because it establishes full-viewport structure (`min-height: 100vh`, a fixed header, sticky panels), it's documented here with its anatomy and code rather than an inline live preview.

```tsx
import { SandboxLayout } from "@harnessio/ui/components";

<SandboxLayout.Root>
  {/* Optional left navigation column (sticky, full height) */}
  <SandboxLayout.LeftPanel>{/* nav */}</SandboxLayout.LeftPanel>

  {/* Optional secondary nav column */}
  <SandboxLayout.LeftSubPanel>{/* sub-nav */}</SandboxLayout.LeftSubPanel>

  <SandboxLayout.Main>
    <SandboxLayout.Header>{/* breadcrumbs / top bar */}</SandboxLayout.Header>
    <SandboxLayout.SubHeader>{/* tabs */}</SandboxLayout.SubHeader>

    <SandboxLayout.Content maxWidth="5xl">
      {/* page content */}
    </SandboxLayout.Content>
  </SandboxLayout.Main>
</SandboxLayout.Root>;
```

## Variations

### Columns

Use `SandboxLayout.Columns` / `SandboxLayout.Column` to split content into a grid. `columnWidths` accepts any CSS `grid-template-columns` value (default `'repeat(2, 1fr)'`).

```tsx
<SandboxLayout.Columns columnWidths="1fr 320px">
  <SandboxLayout.Column>{/* primary */}</SandboxLayout.Column>
  <SandboxLayout.Column>{/* sidebar */}</SandboxLayout.Column>
</SandboxLayout.Columns>
```

## Installation

```tsx
import { SandboxLayout } from "@harnessio/ui/components";

<SandboxLayout.Root>

    </SandboxLayout.Content>
```

## Anatomy

`SandboxLayout` is a set of compound primitives. `SandboxLayout.Root` is a full-height grid (`auto | 1fr`); a navigation column sits in the first track and `SandboxLayout.Main` fills the second.

- **`SandboxLayout.Root`** — the full-height grid shell (`min-height: 100vh`), rendered as `<main role="main">`. It takes `children` only.
- **`SandboxLayout.LeftPanel`** — the primary navigation column (fixed 220px, sticky, full height). It's a `<nav>` and is hidden below the `md` breakpoint.
- **`SandboxLayout.LeftSubPanel`** — an optional secondary nav column (fixed 300px) with a right border and its own scroll. Unlike `LeftPanel`, it stays visible on small screens and is not sticky.
- **`SandboxLayout.Main`** — the main content section (`<section>`). Pass `fullWidth` to let it flex to fill available space.
- **`SandboxLayout.Header`** — a fixed top header (`<header role="banner">`) sized to the breadcrumbs height.
- **`SandboxLayout.SubHeader`** — a secondary header row sized to the tabs-nav height, for section tabs.
- **`SandboxLayout.Content`** — the page body. `maxWidth` (`sm`–`7xl`) constrains and centers the content; leave it off for full-bleed.
- **`SandboxLayout.Columns` / `SandboxLayout.Column`** — a grid container and its cells for multi-column content.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use one `SandboxLayout.Root` per screen as the outermost element of the page.
- Put primary navigation in `LeftPanel` and reserve `LeftSubPanel` for a secondary, context-specific nav.
- Set `Content maxWidth` on reading-heavy pages so lines don't stretch across very wide viewports; leave it off for dashboards and tables that want the full width.

**Don't**

- Don't nest a second `Root` inside the layout — it establishes the viewport grid once.
- Don't rely on `LeftSubPanel` for critical navigation on small screens if it would crowd the content; it isn't hidden below `md` the way `LeftPanel` is.

## Accessibility

### Landmarks

- The parts render as real landmarks: `Root` is `<main role="main">`, `Header` is `<header role="banner">`, `LeftPanel` is a `<nav aria-label="Left Navigation Panel">`, `LeftSubPanel` is a labelled `<section>`, and `Main` is a labelled `<section>`. This gives assistive tech a navigable page structure out of the box.
- `Columns` exposes `role="grid"` with `Column` as `role="gridcell"`.

### Focus & states

- `Header` is fixed and `LeftPanel` is sticky, so they stay in view as `Content` scrolls. Keep interactive elements inside these regions reachable and not obscured by the fixed header.
