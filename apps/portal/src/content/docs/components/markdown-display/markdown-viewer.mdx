The `MarkdownViewer` component renders markdown content with syntax highlighting, interactive task lists, code suggestions, and customizable image handling. It's suited to documentation, comments, READMEs, and code-review content. It renders standard markdown syntax including headings, lists, links, images, tables, blockquotes, and code blocks.

## Anatomy

`MarkdownViewer` takes a markdown string via `source` and renders it. It's built on `@uiw/react-markdown-preview`, with a set of remark/rehype plugins layered on for line breaks, sanitization, video embeds, and external-link handling.

```tsx
<MarkdownViewer source="# Hello" withBorder />
```

- **Source** — `source` (required) is the markdown string to render. Standard syntax is supported: headings, lists, links, images, emphasis, tables, blockquotes, and fenced code blocks.
- **Container** — `withBorder` wraps the content in a bordered, padded container. `maxHeight` caps the container height for scrollable content. `className` styles the outer wrapper; `markdownClassName` styles the rendered markdown element.
- **Typography** — `variant` (`default` / `sm`) selects the typography scale; `muted` renders the text in a muted color.
- **Code blocks** — fenced code is syntax-highlighted by the underlying previewer. `showLineNumbers` adds line numbers, but only for blocks with more than one line.
- **Task lists** — `- [ ]` / `- [x]` items render as real, focusable checkboxes. When you pass `onCheckboxChange`, toggling a checkbox calls it with the **full updated markdown source** string (not an event), so you can persist the change. `isLoading` disables the checkboxes while content is updating.
- **Code suggestions** — a ` ```suggestion ` fence renders through a dedicated suggestion block. `suggestionTitle` sets its header and `suggestionFooter` supplies footer content (e.g. Accept / Reject buttons); `suggestionBlock` supplies the diff source.
- **Images** — `imageUrlTransform` rewrites each image `src` before render (useful for relative paths or proxying). Clicking an image opens it in a new tab.
- **Typewriter** — `speed` (ms per character) reveals the source progressively instead of all at once.

### Plugins & security

- **Plugins** — `remark-breaks` (line breaks → `<br>`), `rehype-sanitize` (HTML sanitization), `rehype-video` (video-file embeds), and `rehype-external-links` (external-link attributes).
- **Sanitization** — output is sanitized; image event handlers and unsafe attributes are stripped as XSS hardening.
- **External links** — get `target="_blank"` and `rel="nofollow noreferrer noopener"`. Internal links and `#` anchors are intercepted and routed/scrolled instead of doing a full navigation.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use `withBorder` when the markdown is a distinct block in the UI (a comment, a README preview); leave it off when the content flows inline with the page.
- Set `maxHeight` for long, user-generated content so it doesn't dominate the layout.
- Use `variant="sm"` in dense contexts like comment threads and inline review notes.

**Don't**

- Don't hand `MarkdownViewer` untrusted HTML expecting it to pass through — HTML is sanitized by design.
- Don't rely on `showLineNumbers` for single-line snippets; line numbers only appear when a block has multiple lines.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Write the `source` as plain markdown — keep headings meaningful and lists parallel, since the viewer renders structure faithfully.
- For task lists, keep item text short and action-oriented ("Add unit tests"), and persist toggles through `onCheckboxChange` rather than treating them as read-only.

## Accessibility

### Labeling

- The viewer renders whatever semantics the markdown implies (headings, lists, tables). Author the `source` with a sensible heading hierarchy so the rendered output is navigable.
- Images use their markdown `alt` text; provide meaningful alt text in the source.

### Focus & states

- Task-list checkboxes are genuine native inputs — they're keyboard-focusable and toggleable, and are disabled when `isLoading` is set.

### Known limitations

- **No added ARIA.** Beyond native element semantics and the sanitize schema, the component doesn't add roles or `aria-*`. There's no live-region announcement when content updates (e.g. during typewriter reveal or loading).
- **Decorative alert icons.** Markdown alert blocks (`> [!NOTE]` etc.) render a decorative icon with no accessible label; the meaning comes from the adjacent text.
