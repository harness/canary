The `Pagination` component allows navigation through pages of content, with "Previous" and "Next" buttons and — in determinate mode — a page-size selector.

There are two modes:

- **Determinate** — pass `totalItems` and `pageSize` so the component knows how many pages exist.
- **Indeterminate** — pass `indeterminate` with `hasNext` / `hasPrevious` when the total isn't known ahead of time; only the Next / Previous controls render.

<DocsPage.ComponentExample
  client:only
  code={`() => {
    const [currentPage, setCurrentPage] = React.useState(1)

    return (
        <div className="w-[550px]">
            <Pagination
                totalItems={100}
                pageSize={10}
                currentPage={currentPage}
                goToPage={setCurrentPage}
            />
        </div>
    )

}`} />

```typescript jsx
import { Pagination } from '@harnessio/ui/components'

//...

const [currentPage, setCurrentPage] = useState(1)

return (
  <Pagination
    totalItems={100}
    pageSize={10}
    currentPage={currentPage}
    goToPage={setCurrentPage}
  />
)
```

### Indeterminate pagination

```typescript jsx
import { Pagination } from '@harnessio/ui/components'

//...

const [currentPage, setCurrentPage] = useState(1)

return (
  <Pagination
    indeterminate
    hasPrevious={currentPage > 1}
    hasNext={currentPage < 100}
    currentPage={currentPage}

    // if need to use links
    getPrevPageLink={() => currentPage - 1}
    getNextPageLink={() => currentPage + 1}

    // if need to use buttons
    onPrevious={() => setCurrentPage(currentPage - 1)}
    onNext={() => setCurrentPage(currentPage + 1)}
  />
)
```

## Anatomy

`Pagination` renders a Previous control, a Next control, and — in determinate mode when `onPageSizeChange` is supplied — an "items per page" select.

- **Mode** — pass `totalItems` + `pageSize` for determinate paging, or `indeterminate` with `hasNext` / `hasPrevious` when the total is unknown.
- **Navigation** — for each direction choose _either_ a callback (`goToPage`, or `onPrevious` / `onNext`) _or_ a link getter (`getPageLink`, or `getPrevPageLink` / `getNextPageLink`). The two styles are mutually exclusive; callbacks render `<button>`s, link getters render anchors styled as buttons.
- **Page size** — providing `onPageSizeChange` shows the select; `pageSizeOptions` customizes its choices (default `[10, 25, 50]`).

```tsx
<Pagination
  totalItems={100}
  pageSize={pageSize}
  currentPage={currentPage}
  goToPage={setCurrentPage}
  onPageSizeChange={setPageSize}
/>
```

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Use determinate pagination whenever you know the total count — it lets people see how far they can go and pick a page size.
- Use indeterminate pagination for cursor-based or streaming data where the total isn't available.
- Keep `pageSizeOptions` short and sensible for the data density of the view.

**Don't**

- Don't mix a callback and a link getter for the same direction — pick one navigation style.
- Don't use pagination for very small lists that fit on a single page; hide it when there's only one page of results.

## Accessibility

### Keyboard

- The Previous / Next controls are standard buttons or links, so they're reachable and activatable with the keyboard in the usual way.

### Labeling

- The Previous and Next controls carry translated `aria-label`s ("Go to previous page" / "Go to next page") so their purpose is announced even though they're icon-only.

### Known limitations

- **No landmark or page-number list in the shipping component.** `Pagination` renders the Previous / Next controls (and optional page-size select) but does not wrap them in a `<nav>` and does not render a numbered page list — so there is no `aria-current` page indicator. If you need a labelled pagination landmark, provide it in the surrounding markup.
