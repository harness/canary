The `Dialog` component provides an accessible and customizable dialog overlay for displaying important content or requesting user input. It supports different sizes, themes, and can include an icon or logo in the header.

## Custom trigger focus

If a dialog is opened without the `Trigger` component (e.g., a dropdown item), focus will not return to the trigger element when the dialog is closed. To address this use `useCustomDialogTrigger` hook to register your custom trigger element.

  client:only
  code={`() => {

      registerTrigger();
      setOpen(true);

return (

  <div className="space-y-cn-sm w-full">

              <DropdownMenu.Item title="Open dialog" onSelect={handleOpenDialog} />

## Anatomy

All parts of the `Dialog` are composed together. It's built on Radix UI's dialog primitive, so it comes with a focus trap, an overlay, and Escape-to-close out of the box.

```tsx
<Dialog.Root>
  <Dialog.Trigger />
  <Dialog.Content>
    <Dialog.Header>
      <Dialog.Title />
      <Dialog.Description />
    </Dialog.Header>
    <Dialog.Body />
    <Dialog.Footer>
      <Dialog.Close />
    </Dialog.Footer>
  </Dialog.Content>
</Dialog.Root>
```

- **Root** — controls the open state; use it uncontrolled, or drive it with `open` / `onOpenChange`.
- **Trigger** — wraps the element that opens the dialog and registers it so focus returns there on close.
- **Content** — the modal surface, rendered in a portal over an overlay. It draws a close (✕) button in the top-right unless `hideClose` is set, and `size` scales it (`sm` → `max`). The `Footer` is pulled to the bottom outside the scrolling area automatically.
- **Header / Title / Description** — the top section. `Title` labels the dialog and `Description` describes it. `Header` takes an `icon` _or_ a `logo` (not both) and a `theme` (`default` / `warning` / `danger`). If you omit a `Description`, a visually-hidden placeholder is inserted so the dialog always has an accessible description.
- **Body** — the main content region; it scrolls on overflow by default (set `scrollable={false}` to opt out).
- **Footer / Close** — the action row. `Close` renders a secondary button that dismisses the dialog and can sit in the footer or stand alone.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Keep a dialog focused on a single task or decision; move anything larger to a full page.
- Pair a `theme="danger"` header with a clearly-labeled destructive action ("Delete"), and keep "Cancel" as the safe default.
- Choose the smallest `size` that fits the content — reserve `max` for genuinely large forms, tables, or dashboards.
- Always give the dialog a `Title`, and a `Description` when the purpose isn't obvious from the title alone.

**Don't**

- Don't hide the close button (`hideClose`) unless the flow requires an explicit choice, and always leave another way out (a Cancel button).
- Don't pass both `icon` and `logo` to a header — only one is allowed and passing both renders nothing.
- Don't stack dialogs; resolve one before opening the next.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Write titles as a short noun phrase or clear action ("Delete item", "Generate clone credential"), in sentence case.
- Keep descriptions to a sentence or two of supporting context — not a place for long instructions.
- Label footer buttons with the action they perform ("Connect", "Create branch") rather than generic "OK".

## Accessibility

`Dialog` is built on Radix UI's dialog, which provides the modal semantics: `role="dialog"`, `aria-modal`, a focus trap, and an overlay that blocks the rest of the page.

### Keyboard

- Opening the dialog moves focus into it; **Tab** / **Shift+Tab** cycle through focusable elements and are trapped inside while it's open.
- **Escape** closes the dialog, and closing returns focus to the element that opened it.

### Labeling

- `Dialog.Title` is wired as the dialog's accessible name (`aria-labelledby`) and `Dialog.Description` as its accessible description (`aria-describedby`).
- The top-right close button is icon-only but carries an accessible label so it's announced as a close control.

### Focus & states

- Focus returns to the `Trigger` on close. When you open a dialog without `Dialog.Trigger` (e.g. from a dropdown item), register the opener with the `useCustomDialogTrigger` hook so focus still returns to it.

### Known limitations

- **A missing description is filled with a placeholder.** If you don't provide a `Dialog.Description`, a visually-hidden "No description available" is inserted to satisfy the accessible-description requirement — screen-reader users will hear that generic text. Provide a real `Description` (or your own `aria-describedby`) whenever the dialog needs context.
- **Icon and logo are mutually exclusive.** Passing both `icon` and `logo` to `Header` logs a warning and renders nothing — choose one.
