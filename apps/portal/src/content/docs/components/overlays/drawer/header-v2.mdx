## Headers

`Drawer.Header` accepts a structured, opinionated set of props that consolidate tagline/breadcrumb, icon/logo, title, description, actions, metadata (children), and tabs into a single standardized layout with optional loading state. Pass a `title` prop to opt into this layout; pass children (`Drawer.Title`, `Drawer.Tagline`, `Drawer.Description`) to use the legacy compositional layout instead. Both are supported on the same component so existing usage keeps working.

> **Deprecated:** `Drawer.HeaderV2` is now an alias of `Drawer.Header` with these props. Prefer `Drawer.Header` for new usage.

### With tabs

Wrap the drawer content in a `Tabs.Root` to enable tab switching. `Drawer.HeaderV2` renders the tab strip at the bottom of the header when `tabs` is provided.

<DocsPage.ComponentExample
  client:only
  code={`() => {
    const [tab, setTab] = React.useState('overview');

    return (
      <Drawer.Root>
        <Drawer.Trigger>
          <Button>HeaderV2 with Tabs</Button>
        </Drawer.Trigger>

        <Drawer.Content size="md">
          <Tabs.Root value={tab} onValueChange={setTab}>
            <Drawer.Header
              title="Build #1234"
              tagline="Pipelines / main"

## Footers

`Drawer.Footer` accepts a structured, opinionated set of props that standardize the footer's action bar: a `tertiaryButton` pinned to the far left, plus `secondaryButton` and `primaryButton` right-aligned. Every button is optional and takes a `ReactNode`, so you keep full control over each button (wrap it in `Drawer.Close`, set `loading`, `disabled`, `iconOnly`, etc.) while the layout and spacing stay consistent across every drawer. Pass any of `primaryButton` / `secondaryButton` / `tertiaryButton` to opt into this layout; pass children only (e.g. `ButtonLayout`) to use the legacy compositional layout instead. Both are supported on the same component so existing usage keeps working.

Content passed as `children` in the structured mode renders as a slot above the action bar.

**Button placement rule.** When you have two actions, a primary and a secondary, default to **two buttons on the right** (`secondaryButton` + `primaryButton`). The left `tertiaryButton` slot is reserved for a **backward action** (e.g. a "Back" button in a multi-step flow) — or for a **cancel/close**, but only when the `secondaryButton` position isn't already a cancel/close. Pass a ghost-variant button (`<Button variant="ghost">`) here so it reads as the lowest-emphasis action. In other words, never place a cancel/close in both the left slot and the secondary slot: if the secondary action is a cancel/close, leave the left slot empty; if it isn't, the left slot may hold the cancel/close (or a back action). The [dual pane wizard](/components/overlays/drawer/#dual-pane-drawer) shows this — a ghost "Back" sits in the left slot while stepping through, and on the first step (where there's no backward action) the "Cancel" takes the left slot instead.

### Basic

<DocsPage.ComponentExample
  client:only
  code={`
    <Drawer.Root>
      <Drawer.Trigger>
        <Button>Open Drawer with structured footer</Button>
      </Drawer.Trigger>

      <Drawer.Content size="md">
        <Drawer.Header title="Deploy service" description="Review and confirm your deployment" icon="deploy-solid" />
        <Drawer.Body>
          <p>Drawer body content goes here.</p>
        </Drawer.Body>
        <Drawer.Footer
          tertiaryButton={<Button variant="ghost">Back</Button>}
          secondaryButton={
            <Drawer.Close asChild>
              <Button variant="outline">Secondary action</Button>
            </Drawer.Close>
          }
          primaryButton={<Button>Primary action</Button>}
        />
      </Drawer.Content>
    </Drawer.Root>

`}
/>
