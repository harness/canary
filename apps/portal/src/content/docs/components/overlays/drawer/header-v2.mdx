## Headers

`Drawer.Header` is the recommended header. Pass a `title` prop to opt into the **structured** layout — a single standardized header exposing the fullest set of props (tagline/breadcrumb, icon/logo, title, description, actions, metadata (children), and tabs) with an optional loading state, so it covers the widest range of use cases. The same component still supports the legacy **compositional** pattern (`Drawer.Header` > `Drawer.Title` > `Drawer.Description`) for simpler headers — omit `title` and pass those children instead.

`Drawer.HeaderV2` is a **deprecated alias** for the structured header: it renders identically to `Drawer.Header` with a `title`, so existing usage keeps working, but new code should use `Drawer.Header`.

Toggle props to explore the header. The preview updates live, and **Show code** reflects the current configuration.

## Footers

`Drawer.Footer` accepts a structured, opinionated set of props that standardize the footer's action bar: a `tertiaryButton` pinned to the far left, plus `secondaryButton` and `primaryButton` right-aligned. Every button is optional and takes a `ReactNode`, so you keep full control over each button (wrap it in `Drawer.Close`, set `loading`, `disabled`, `iconOnly`, etc.) while the layout and spacing stay consistent across every drawer. Pass any of `primaryButton` / `secondaryButton` / `tertiaryButton` to opt into this layout; pass children only (e.g. `ButtonLayout`) to use the legacy compositional layout instead. Both are supported on the same component so existing usage keeps working.

Content passed as `children` in the structured mode renders as a slot above the action bar.

Toggle props to explore the footer. Each button's text is its label — clear it to hide that button. The preview updates live, and **Show code** reflects the current configuration.

## Best practices

### Prefer the structured `Drawer.Header`

Reach for `Drawer.Header` with a `title` (the structured layout) by default — its richer prop set handles the most use cases. Fall back to the compositional pattern (`Drawer.Header` > `Drawer.Title` > `Drawer.Description`) only for simple, one-off headers. Avoid `Drawer.HeaderV2` in new code; it's a deprecated alias for the same structured header.

### Don't number a title that has an icon

Don't combine an icon or logo with a number in the title — for example, avoid `[icon/logo] 1. Step description`. Pick one leading element: an icon or logo for identity, or a number for sequence, but not both.

### Footer button placement

When you have two actions, a primary and a secondary, default to **two buttons on the right** (`secondaryButton` + `primaryButton`). The left `tertiaryButton` slot is reserved for a **backward action** (e.g. a "Back" button in a multi-step flow) — or for a **cancel/close**, but only when the `secondaryButton` position isn't already a cancel/close. Pass a ghost-variant button (`<Button variant="ghost">`) here so it reads as the lowest-emphasis action.

Never place a cancel/close in both the left slot and the secondary slot: if the secondary action is a cancel/close, leave the left slot empty; if it isn't, the left slot may hold the cancel/close (or a back action). The [dual pane wizard](/components/overlays/drawer/dual-pane/) shows this — a ghost "Back" sits in the left slot while stepping through, and on the first step (where there's no backward action) the "Cancel" takes the left slot instead.
