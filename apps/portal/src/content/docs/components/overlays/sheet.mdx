The `Sheet` component is a panel that slides in from an edge of the screen for overlaid content — settings, details, or a focused task off to the side. It's a compound component built on Radix Dialog, composed from `Sheet.Root`, `Sheet.Trigger`, `Sheet.Content`, and the structural parts `Sheet.Header`, `Sheet.Footer`, `Sheet.Title`, and `Sheet.Description`.

## Variations

`Sheet.Content` slides in from the `right` by default. Set `side` to `left`, `top`, or `bottom` to change the edge it appears from.

## Anatomy

All parts of the `Sheet` component can be imported and composed as required.

```tsx
<Sheet.Root>
  <Sheet.Trigger />
  <Sheet.Content>
    <Sheet.Header>
      <Sheet.Title />
      <Sheet.Description />
    </Sheet.Header>
    {/* body content */}
    <Sheet.Footer />
  </Sheet.Content>
</Sheet.Root>
```

- **`Sheet.Root`** — the Radix Dialog root that holds open state. Control it with `open` / `onOpenChange`, or leave it uncontrolled with `defaultOpen`.
- **`Sheet.Trigger`** — the element that opens the sheet. Use `asChild` to render your own `Button` as the trigger.
- **`Sheet.Content`** — the sliding panel. Sets the `side`, renders a built-in close button (unless `hideCloseButton`), and portals itself above the page with an overlay.
- **`Sheet.Header`** / **`Sheet.Footer`** — layout regions for the title/description and for actions.
- **`Sheet.Title`** / **`Sheet.Description`** — the accessible name and supporting text; Radix wires them to the dialog automatically.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Always include a `Sheet.Title` — it names the dialog for assistive tech (Radix warns when it's missing). Use `Sheet.Description` for a short supporting line.
- Put confirming/cancelling actions in `Sheet.Footer` so they sit in a predictable place.
- Choose `side` to match the mental model: side panels for supporting detail, `bottom` for mobile-style actions.

**Don't**

- Don't stack multiple sheets on top of each other; open one focused panel at a time.
- Don't hide the close button (`hideCloseButton`) unless you provide another obvious way to dismiss the sheet.

## Content

{/* TODO: editorial — please review against product guidance. */}

- Keep the title a short noun phrase describing what the sheet is for ("Filters", "Pipeline settings").
- Use the description for a single clarifying sentence — move longer guidance into the body.

## Accessibility

### Keyboard

- Built on Radix Dialog: `Esc` closes the sheet, focus moves into the panel on open and returns to the trigger on close, and focus is trapped within the panel while it's open.

### Labeling

- `Sheet.Title` and `Sheet.Description` are wired to the dialog's `aria-labelledby` / `aria-describedby` automatically. The built-in close button carries an `sr-only` "Close" label.

### Focus & states

- The panel opens as a `role="dialog"` with `aria-modal`. With `modal` (the default) the rest of the page is inert behind the overlay; set `modal={false}` for a non-blocking panel.
