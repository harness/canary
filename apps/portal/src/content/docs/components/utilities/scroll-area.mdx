The `ScrollArea` component offers a flexible, customizable container with scrollbars for overflowing content. Use it to display content that exceeds the visible area, supporting both horizontal and vertical scrolling.

### Scroll events

The `ScrollArea` component provides several event handlers to respond to scroll actions:

- `onScrollTop`: Triggered when the scroll area is scrolled to the top.
- `onScrollBottom`: Triggered when the scroll area is scrolled to the bottom.
- `onScrollLeft`: Triggered when the scroll area is scrolled to the left.
- `onScrollRight`: Triggered when the scroll area is scrolled to the right.

Each handler receives an `IntersectionObserverEntry` describing the position and visibility of the edge sentinel.

`rootMargin` and `threshold` customize when the events fire. Use `rootMargin` to adjust the offset around the scroll area, and `threshold` to define how much of the target should be visible before triggering the scroll event.

## Anatomy

`ScrollArea` wraps your content in a scrolling viewport. Give the viewport a fixed size (via `className`) and let the inner content overflow — the component handles the scrollbars and, optionally, edge-detection callbacks.

```tsx
<ScrollArea className="w-[300px] h-[200px]">
  {/* overflowing content */}
</ScrollArea>
```

- The outer element is the scroll viewport; `className` styles it and `classNameContent` styles the inner content wrapper.
- Edge callbacks (`onScrollTop` / `onScrollBottom` / `onScrollLeft` / `onScrollRight`) are backed by `IntersectionObserver` sentinels placed at each edge; a sentinel is only rendered when its callback is provided.
- Pass `preserveScrollPosition` with a `storageKey` to persist and restore the vertical scroll position across mounts.

## Best practices

{/* TODO: editorial — please review against product guidance. */}

**Do**

- Constrain the viewport with an explicit width/height so there's something to scroll within.
- Use the edge callbacks for infinite-scroll or "load more" behavior — `onScrollBottom` is the usual hook for fetching the next page.
- Tune `rootMargin` / `threshold` when you want to fetch slightly before the user actually reaches the edge.

**Don't**

- Don't attach an edge callback you don't use — the sentinel and observer are only created for callbacks you pass.
- Don't rely on it for the whole-page scroll; it's for bounded, overflowing regions.

## Accessibility

### Focus & states

- `ScrollArea` renders plain scrollable containers (it isn't built on a Radix scroll primitive) and doesn't add ARIA roles. Native keyboard scrolling applies once the region is focused.

### Known limitations

- Because no `role` or label is applied, give the region an accessible name in surrounding markup if its purpose isn't clear from context, and make sure keyboard users can reach the scrollable content.
