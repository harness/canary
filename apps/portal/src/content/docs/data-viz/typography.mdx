Chart text uses the same two typefaces and weights as the rest of the design system — Inter at 400 and 500 — so there are no raw font values in chart code. Sizes and line heights come from the `chart.*` text tokens below, or from the shared text styles where the chart needs nothing special.

## Shared text styles

## Continuous value scaling

Center values — the big number in a donut or gauge — scale **continuously**. They are not snapped to a fixed set of sizes. This is intentional: it looks better in production, because the number always fills the ring as well as it can.

The size is calculated in dashboard-ui each time a chart renders:

1. Take half the inner radius of the ring.
2. Take the largest size at which the text fits within 85% of the ring width. This depends on how many characters the value has.
3. Use the smaller of the two, and never go above 64px.

A few things follow from this:

- **Smaller chart, smaller number.** The size follows the chart itself, not the screen. The same donut shows a smaller number in a narrow card than in a wide one.
- **Longer text, smaller number.** A long value such as `20h 28m 29s` is smaller than `300` in the same chart, because it has to fit the ring.
- **Any size can appear.** You may see sizes such as 23px, 30px or 32px. These are expected, not errors.
- **Labels scale less.** The label above a value ("Total", "Low") follows the ring too, but stays between 12px and 15px.

<Aside type="caution" title="Do not round to a scale">
  Don't replace the calculated size with a fixed step or a text token. `chart.donut.value.sm` and `chart.gauge.value.number` are reference sizes only. Fixed sizes would make numbers overflow small rings or look undersized in large ones.
</Aside>
