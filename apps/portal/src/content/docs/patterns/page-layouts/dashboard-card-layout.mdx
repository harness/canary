A page built from cards laid out on a 12-column grid. It is the layout behind dashboards, analytics and billing pages. In product code this is `Page.Root` with `Page.HeaderV2`, then `Layout.Grid columns={12}` holding `Card.Root` widgets.

## Metrics, chart and table

The most common dashboard. A row of KPI cards on top, a wide chart beside a ranked list, then a full-width table. Each KPI card spans 3 columns, the chart spans 8 and the list spans 4.

## Anatomy

1. **Page header.** Breadcrumb, title, description and the page actions, such as Refresh and Edit. Add tabs when the page has several areas.
2. **Filter bar (optional).** Time range and scope filters that apply to every card on the page.
3. **Card grid.** A 12-column grid, `Layout.Grid columns={12} gap="sm"`. Cards span whole numbers of columns.
4. **Card header.** A title, with an optional subtitle for scope such as "Last 14 days".
5. **Card body.** A value, chart, list or table.

## Guidelines

- Use the 12-column grid for dashboards. Spans of 3, 4, 6, 8 and 12 cover almost every layout.
- Make KPI cards span 3 or 4 columns so they sit in one row. Put charts at 6 or 8 columns and tables at 12.
- Set `gridAutoRows` to a minimum height rather than a fixed one so cards grow with their content.
- Use `gap="sm"` between cards so the grid reads as one surface.
- Give every card a title. Add a subtitle only when it adds scope, such as the time range.
- Keep page actions in the header, not inside cards. Card menus are for actions on that card.
- Put filters that apply to the whole page in a filter bar above the grid. Do not repeat them inside cards.
- On narrow screens the grid collapses to a single column, so order cards by importance.
- Show empty and error states inside the card, so one failed card does not break the page.
