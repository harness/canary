## Anatomy

1. **Page header.** Breadcrumb, page title, a short description and the page's primary action. Add underlined tabs when the page has related areas of the same subject.
2. **Primary action.** One button at the end of the title row, such as "Create pipeline". Secondary actions go in a menu next to it.
3. **Toolbar (optional).** Search and filters above the content, aligned to the content edges.
4. **Content area.** Fills the width under the header: a table, a list or a set of cards.
5. **Status footer (optional).** A thin bar pinned below a full-height studio or editor page. It shows status such as problem counts and when the page was last edited. It never holds actions.

## Guidelines

- Set `scrollable` on `Page.Root` so the whole page scrolls and the header sticks to the top.
- Use `maxWidth` on the content to switch between a centered page width and full width. Tables and dashboards usually use full width; forms and reading content use the page width.
- Studio-style pages override the scrolling so the content fills the height and scrolls inside itself.
- Use header tabs for two or three related areas. For four or more sections of one subject, use the [page with section menu](/patterns/page-layouts/page-with-section-menu/).
- Keep one primary action per page.

### Footer

- Use a footer only on full-height studio or editor pages, such as the pipeline studio and the chaos experiment studio. Do not add one to list, overview or form pages.
- The footer holds status, not actions. Good content is problem counts, last edited time and author, or the current branch.
- Keep primary actions in the header. Create and edit flows use a drawer, so they never need a footer for Cancel and Save.
- Give the footer a fixed height, a top border and the same horizontal padding as the content. Put the most important status on the left and metadata on the right.
- Pin it below the content. The canvas scrolls inside itself above the footer, never the footer and never the whole page.
