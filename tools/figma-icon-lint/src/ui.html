Before linting, update this branch from main so every shipped name is on the page.

✅ Review checklist

  • On the correct page (icons-to-dev icons, brands-to-dev logos)
  • Name: dot-prefixed, kebab-case, noun-first, right family prefix
  • A COMPONENT, 16x16 (icon) or 22x22 (logo)
  • Reads at actual size; stroke weight and optical size match its neighbours
  • Logos: description holds the brand hex and the mark is visible on it
  • No existing component was deleted or renamed on the branch

💡 About this plugin

Checks new icons and logos before they are merged into the main HDS Icons 3.0 Figma file. Developers publish from that Figma file into the canary code repo (@harnessio/ui), so problems get fixed here in Figma instead of after they have shipped in code.

  1. Work on your Figma branch, on the icons-to-dev (icons) or brands-to-dev (logos) page.
  2. Select your component and click Lint selection, or click Lint whole page to also catch name clashes.
  3. Fix every error. Warnings are worth a look but do not block you.
  4. Re-run until it is clean, then ask an admin to review and merge your branch.

It only reads your file. It never changes your design and sends nothing anywhere.

⭐ Next step: once an admin has merged your branch into main, open Claude Code or Cursor in the canary repo and ask it to publish your icon or logo (for example, “Publish the <name> icon to canary”). The publish skill exports it, adds it to the code, and drafts the Jira ticket and pull request for your approval.
